# .gitignore 적용 및 소급 적용 프로세스

`.gitignore` 파일은 Git이 관리하지 말아야 할 파일 목록을 정의합니다. 하지만 이미 커밋되어 Git 저장소에 기록된 파일은 단순히 `.gitignore`에 이름을 올리는 것만으로는 추적을 멈출 수 없습니다. 이미 '추적(Tracked)' 상태가 된 파일에 대해 설정을 소급 적용하는 방법을 정리합니다.

---

## 1. 동작 원리의 이해

Git은 파일을 세 가지 상태로 관리합니다. `.gitignore`는 오직 **Untracked(추적되지 않은)** 상태의 파일에만 영향을 미칩니다.

* **Tracked**: 이미 Git이 관리하고 있는 상태 (Staging Area나 Commit 내역에 존재)
* **Untracked**: 새로 생성되어 Git이 존재만 알고 있는 상태
* **Ignored**: `.gitignore`에 의해 의도적으로 무시된 상태

이미 커밋된 파일은 **Tracked** 상태이므로, 이를 **Untracked**로 강제 전환한 뒤에야 `.gitignore` 설정이 작동하게 됩니다.

---

## 2. 시나리오: AWS 설정 파일 소급 적용

이미 `config/aws_key.txt` 파일이 커밋된 상황에서, 이를 뒤늦게 `.gitignore`에 등록하고 저장소에서 제외하는 실습 과정입니다.

### Step 1: .gitignore 파일 수정

먼저 제외할 파일 패턴을 `.gitignore`에 추가합니다.

```bash
# .gitignore 파일 내용
config/aws_key.txt

```

### Step 2: 캐시(Index)에서 파일 제거

파일의 실체는 보존하되, Git의 추적 목록에서만 삭제합니다.

```bash
git rm --cached config/aws_key.txt

```

### Step 3: 변경 사항 커밋 및 푸시

인덱스에서 삭제된 정보를 저장소에 반영합니다.

```bash
git add .
git commit -m "Remove sensitive AWS config from tracking"
git push origin main

```

---

## 3. 설정 시 유의사항

* **패턴 작성**: `*.log` (모든 로그 파일), `/node_modules` (특정 폴더), `config/*.json` (특정 폴더 내 확장자) 등 와일드카드를 활용할 수 있습니다.
* **빈 폴더**: Git은 기본적으로 빈 폴더를 추적하지 않습니다. 폴더 구조를 유지하고 싶다면 폴더 안에 `.gitkeep` 파일을 생성하고 해당 파일만 예외적으로 추적해야 합니다.

---

## 4. 보안 및 과금 관리

설정 파일(.env, credentials)이 이미 한 번이라도 퍼블릭 리포지토리에 커밋되었다면, 캐시를 지우더라도 **Git History(이전 커밋 기록)**에는 해당 내용이 남아 있습니다.

> [!CAUTION]
> **보안 위협 및 비용 경고**:
> * **기록 삭제**: `bfg-repo-cleaner`나 `git filter-repo` 같은 도구를 사용하여 커밋 히스토리 전체에서 해당 파일을 완전히 삭제해야 안전합니다.
> * **AWS 과금 방지**: 공개된 Access Key를 통해 누군가 GPU 인스턴스(P계열)나 고성능 인스턴스를 다수 생성할 경우, 하루 만에도 **수백만 원 이상의 과금**이 발생할 수 있습니다. 키가 노출되었다면 지체 없이 IAM 콘솔에서 키를 삭제하십시오.
>
