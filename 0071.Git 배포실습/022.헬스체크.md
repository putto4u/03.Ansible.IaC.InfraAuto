## 앤서블 기반 호스트별 상태 점검 및 자동 푸시 설정

앤서블(Ansible)을 사용하여 여러 대의 서버 상태를 점검할 때, 어떤 서버에서 에러가 발생했는지 식별하기 위해 `inventory_hostname` 변수를 활용합니다. 이를 통해 서버별로 독립적인 상태 리포트를 생성하고 깃허브(GitHub) 저장소에 기록할 수 있습니다.

---

### 1. 호스트네임이 포함된 앤서블 플레이북 수정

각 서버의 식별자를 파일명이나 내용에 포함하여 깃허브에 전송하는 구성입니다.

```yaml
- hosts: web_db_servers
  gather_facts: no
  tasks:
    - name: 웹 서비스(Nginx) 상태 점검
      command: systemctl is-active nginx
      ignore_errors: yes
      register: web_status

    - name: DB 서비스(MariaDB) 상태 점검
      command: systemctl is-active mariadb
      ignore_errors: yes
      register: db_status

    - name: 에러 발생 시 호스트별 리포트 생성 및 전송
      # 관리 노드(localhost)에서 실행하여 깃허브로 푸시
      delegate_to: localhost
      shell: |
        REPORT_FILE="status/error_{{ inventory_hostname }}.log"
        TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
        
        echo "[$TIMESTAMP] 호스트: {{ inventory_hostname }}" > $REPORT_FILE
        echo "Nginx 상태: {{ web_status.stdout }}" >> $REPORT_FILE
        echo "MariaDB 상태: {{ db_status.stdout }}" >> $REPORT_FILE
        
        git add $REPORT_FILE
        git commit -m "Alert: Error detected on {{ inventory_hostname }}"
        git push origin main
      # 서비스가 active가 아닌 경우에만 실행
      when: web_status.stdout != "active" or db_status.stdout != "active"

```

---

### 2. 앤서블의 실행 메커니즘: Cron vs Listen

앤서블은 기본적으로 **푸시(Push) 기반의 절차적 도구**이며, 스스로 네트워크 신호를 기다리는 '리슨(Listen)' 모드로 동작하지 않습니다.

* **실행 방식**: 관리 노드(Control Node)에서 명령을 내리는 순간에만 대상 서버에 접속하여 작업을 수행하고 연결을 종료합니다.
* **주기적 실행(1분 단위)**: 앤서블이 1분마다 작동하게 하려면 관리 노드의 **크론(Cron)** 설정을 이용해야 합니다.

#### 크론탭(Crontab) 설정 예시

관리 노드에서 아래 명령을 등록하여 매 분마다 플레이북을 실행합니다.

```bash
# crontab -e 실행 후 추가
* * * * * /usr/bin/ansible-playbook -i /path/to/hosts /path/to/health_check.yml

```

### 3. 클라우드 서비스 비용 및 인프라 주의사항

자동화 환경 구축 시 발생하는 비용 요소입니다.

| 항목 | 상세 내용 | 과금 및 주의사항 |
| --- | --- | --- |
| **AWS EC2** | 관리 노드 및 대상 서버 운영 | **유료 전환 주의**: 인스턴스 실행 시간에 비례하여 비용 발생. 1분 단위 체크를 위해 24시간 구동 시 월별 가동 시간 확인 필수. |
| **AWS EventBridge** | 앤서블 실행 스케줄링 (SaaS형) | 크론 대신 AWS 서비스를 사용하여 앤서블을 실행할 경우, **스케줄 규칙 실행 횟수**에 따라 비용 발생. |
| **GitHub Actions** | 셀프 호스트 러너 통신 | 깃허브로 빈번하게 `push`할 경우, 저장소 용량 제한 및 API 호출 속도 제한(Rate Limit)을 준수해야 함. |
