그렇습니다. `ansible-vault`는 직접 파일을 수정하는 대신 **"금고(Vault)를 열어서(Decrypt) 수정하고 다시 닫는(Encrypt)"** 방식을 사용하기 때문입니다.

전체적인 흐름을 실제 터미널에서 작업하는 순서대로 정리해 드립니다. 이 과정을 거치면 왜 `vi`가 열리는지 완벽히 이해하실 수 있습니다.

---

## 1. Ansible Vault 작업 전체 흐름

| 단계 | 실행 명령어 | 상태 및 동작 |
| --- | --- | --- |
| **1. 파일 생성** | `touch vault.yml` | 평문(Plaintext) 빈 파일 상태 |
| **2. 암호화** | `ansible-vault encrypt vault.yml` | 암호화(Encrypted) 상태 (내용물 없음) |
| **3. 수정 시도** | `ansible-vault edit vault.yml` | **비밀번호 입력 후 `vi` 편집기가 열림** |
| **4. 내용 작성** | (vi 편집기 안에서 내용 입력) | 메모리상에서만 평문으로 편집 중 |
| **5. 저장/종료** | `:wq` 입력 | **자동으로 다시 암호화되어 저장됨** |

---

## 2. 왜 `vi`가 열리나요?

`ansible-vault edit` 명령어를 실행하면 Ansible은 내부적으로 다음과 같은 일을 수행합니다.

1. 사용자가 입력한 비밀번호로 파일을 임시로 **복호화**합니다.
2. 복호화된 내용을 시스템의 **임시 디렉토리**에 파일로 저장합니다.
3. 시스템의 기본 편집기(대부분 `vi` 또는 `vim`)를 실행하여 그 임시 파일을 엽니다.
4. 사용자가 편집을 마치고 저장(`:wq`)하면, 그 내용을 다시 **암호화**하여 원래 파일에 덮어씁니다.
5. 작업에 사용된 임시 파일을 삭제하여 흔적을 지웁니다.

---

## 3. 실무 운영 및 환경 설정

* **기본 편집기 변경 (무료):** 만약 `vi`가 익숙하지 않아 `nano` 등을 사용하고 싶다면, 터미널 환경 변수를 설정하여 변경할 수 있습니다.
* `export EDITOR=nano`

`ansible-vault encrypt` 또는 `edit` 명령을 실행했을 때 비밀번호를 묻는 것은 정상적인 보안 절차입니다. 하지만 매번 수동으로 비밀번호를 입력하는 것은 자동화의 효율성을 떨어뜨리므로, **비밀번호 파일(`.vault_pass`)을 사용하여 이를 자동화**하는 실무 설정법을 안내해 드립니다.

## 1. Vault 비밀번호 자동화 설정

비밀번호를 파일에 저장하고 Ansible이 이를 자동으로 읽어가도록 설정하면, 더 이상 터미널에서 비밀번호를 묻지 않습니다.

### **Step 1: 비밀번호 파일 생성**

프로젝트 루트 디렉토리에 암호화 시 사용했던 비밀번호를 텍스트 파일로 저장합니다.

```bash
# ~/projects/ans_pj1 경로에서 실행
echo "여러분이_설정한_비밀번호" > .vault_pass

# 보안을 위해 소유자만 읽을 수 있도록 권한 제한 (필수)
chmod 600 .vault_pass

```

### **Step 2: ansible.cfg에 등록**

Ansible이 실행될 때 해당 파일을 참조하도록 설정 파일에 경로를 추가합니다.

```ini
# ansible.cfg
[defaults]
inventory = ./hosts
vault_password_file = ./.vault_pass  # 비밀번호 파일 경로 지정

```

이렇게 설정하면 이후 `ansible-vault edit`이나 `ansible-playbook` 실행 시 **비밀번호를 묻지 않고 즉시 실행**됩니다.
