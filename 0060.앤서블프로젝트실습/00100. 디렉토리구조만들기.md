### Ansible 프로젝트 디렉토리 구조 자동화 (setup.yml)

Ansible 프로젝트의 표준화된 디렉토리 구조(Best Practice)를 로컬 제어 노드에 자동으로 생성하는 플레이북입니다. 수동으로 폴더를 하나씩 만들지 않고, 이 스크립트를 통해 일관성 있는 환경을 즉시 구축할 수 있습니다.

```yaml
# 실행 방법: 터미널에서 'ansible-playbook setup.yml' 입력
- name: 프로젝트 기초 구조 생성
  hosts: localhost          # 원격 서버가 아닌, 앤서블이 설치된 제어 노드(로컬)에서 실행
  connection: local         # 로컬 작업이므로 SSH 연결 과정을 생략하여 속도 향상
  gather_facts: no          # 디렉토리 생성에는 OS 정보(IP, CPU 등)가 필요 없으므로 수집 생략 (속도 최적화)
  
  tasks:
    - name: 롤(Role) 및 변수 디렉토리 생성
      file:                 # 파일, 디렉토리, 심볼릭 링크 등을 관리하는 핵심 모듈
        path: "{{ item }}"  # 아래 loop 문에서 정의한 리스트의 각 항목이 여기에 순차적으로 대입됨
        state: directory    # 지정된 경로가 '디렉토리'로 존재하도록 보장 (없으면 생성, 파일이면 에러)
        recurse: yes        # (선택 사항) 하위 디렉토리까지 재귀적으로 생성 (mkdir -p 와 유사 효과)
      loop:                 # 반복문 시작 (리스트의 개수만큼 위 task를 반복 실행)
        # 1. 전역 변수 디렉토리
        - group_vars/all            # 모든 호스트에 공통으로 적용될 변수 파일(vars.yml 등) 위치
        
        # 2. 공통(Common) 롤: 모든 서버에 기본적으로 수행할 작업 (예: 패키지 업데이트, 시간 동기화)
        - roles/common/tasks        
        
        # 3. 데이터베이스(MariaDB) 롤
        - roles/mariadb/tasks       # MariaDB 설치, 서비스 시작 등의 작업 명세
        - roles/mariadb/templates   # my.cnf 등 설정 파일의 Jinja2 템플릿(.j2) 저장소
        
        # 4. 웹 서버(Nginx) 롤
        - roles/nginx/tasks         # Nginx 설치 및 가상 호스트 설정 작업 명세
        - roles/nginx/templates     # nginx.conf, default.conf 등 설정 템플릿 저장소
        
        # 5. 웹 애플리케이션(Webapp) 롤
        - roles/webapp/tasks        # 소스 코드 배포, 권한 설정 등의 작업 명세
        - roles/webapp/templates    # 애플리케이션별 config 파일 템플릿 저장소

```

#### 코드 해설 및 주요 포인트

1. **`hosts: localhost` & `connection: local**`:
* 이 플레이북은 서버를 세팅하는 것이 아니라, **작업 공간(Workspace)을 세팅**하는 것이 목적입니다. 따라서 SSH를 통해 외부로 나가지 않고 로컬에서 파일 시스템 작업만 수행하도록 설정합니다.


2. **`gather_facts: no`**:
* 단순히 폴더를 만드는 작업에 시스템의 하드웨어/네트워크 정보를 수집하는 시간(약 1~3초)을 낭비할 필요가 없습니다. 이를 끄면 실행 즉시 작업이 시작됩니다.


3. **`state: directory`의 멱등성(Idempotency)**:
* 이 스크립트는 여러 번 실행해도 안전합니다. 이미 해당 디렉토리가 존재하면 아무 작업도 하지 않고(Changed=0), 없을 때만 생성(Changed=1)합니다.


4. **`roles/` 구조의 의미**:
* Ansible은 거대한 하나의 파일보다 기능별(DB, Web, Common)로 역할을 나누는 **Role 기반** 구성을 권장합니다.
* **`tasks`**: 실제 실행할 명령어들의 리스트 (`main.yml`).
* **`templates`**: 설정 파일의 원본(Jinja2 템플릿)을 저장. 실행 시 변수가 치환되어 서버로 전송됩니다.
