앤서블 실행 시 `-k`(SSH 암호)와 `-K`(Sudo 암호) 옵션을 제거하고 완전 자동화를 구현하기 위해서는 **신뢰 관계 형성(SSH Key)**과 **권한 위임 설정(NOPASSWD)**이 선행되어야 합니다. 이 설정이 완료되면 앤서블은 추가 입력 없이도 대상 서버를 제어할 수 있습니다.

---

### 1. SSH 접속 암호(`-k`) 제거: SSH 키 기반 인증

가장 권장되는 방법은 비밀번호 대신 비대칭키(Public/Private Key)를 사용하여 서버에 접속하는 것입니다.

1. **관리 PC에서 SSH 키 생성** (이미 있다면 생략):
```bash
# 엔터만 입력하여 기본 경로(~/.ssh/id_rsa)에 생성
ssh-keygen -t rsa -b 4096

```


2. **대상 서버로 공개키 복사**:
```bash
# 인벤토리에 있는 모든 서버에 대해 수행
ssh-copy-id 유저명@서버IP

```


*이 과정에서 마지막으로 서버 암호를 입력하면, 이후부터는 암호 없이 접속이 가능해집니다.*

### 2. Sudo 암호(`-K`) 제거: 두 가지 전략

#### 방법 A: 대상 서버의 sudoers 설정 (가장 깔끔한 방법)

대상 서버에서 특정 유저가 `sudo` 명령을 내릴 때 암호를 묻지 않도록 설정합니다.

1. **대상 서버에서 설정 편집**: `sudo visudo`
2. **하단에 내용 추가**:
```text
# 유저명이 'ubuntu'인 경우
ubuntu ALL=(ALL) NOPASSWD:ALL

```


*이 설정을 마치면 앤서블의 `become: yes` 작업 시 암호를 묻지 않습니다.*

#### 방법 B: Ansible Vault 변수 활용 (서버 설정을 못 바꿀 때)

서버의 sudoers 설정을 바꿀 수 없다면, `vault.yml`에 Sudo 암호를 저장하고 앤서블이 이를 꺼내 쓰도록 맵핑합니다.

1. **`group_vars/all/vault.yml` 수정**:
```yaml
ansible_become_password: "서버_Sudo_비밀번호"

```


2. **동작 원리**: 앤서블은 `ansible_become_password`라는 변수가 정의되어 있으면 `-K` 옵션이 없어도 이 값을 사용합니다.

### 3. 최종 완성된 'Zero-Prompt' 실행 환경

위 설정을 모두 마친 후, Vault 비밀번호 파일까지 준비하면 명령어 하나로 모든 것이 끝납니다.

1. **비밀번호 파일 생성**: `echo "vault_password" > .vault_pass`
2. **실행**:
```bash
ansible-playbook -i inventory.ini site.yml --vault-password-file .vault_pass

```


*이제 `-k`, `-K`, `--ask-vault-pass`를 모두 입력할 필요가 없습니다.*

### 💰 AWS 과금 및 유료 전환 주의사항

인증 자동화 실습 시 발생할 수 있는 AWS 비용 항목입니다.

* **Instance Running Time**: SSH 키 배포 및 sudoers 설정 테스트를 위해 여러 인스턴스를 켜두는 시간이 길어질 경우, **프리티어 월 750시간**을 초과하면 과금이 시작됩니다.
* **Public IPv4 Address**: 앤서블 컨트롤 노드와 대상 노드가 각각 공인 IP를 가질 경우, **사용 중인 모든 공인 IP에 대해 시간당 약 $0.005**의 비용이 발생합니다. (AWS 2024년 정책 변경 사항)
* **EBS Storage**: 자동화 과정에서 여러 대의 인스턴스를 생성했다면, 각 인스턴스에 할당된 EBS 볼륨의 합계가 **30GB**를 넘지 않도록 주의하십시오. 초과 시 월 GB당 비용이 청구됩니다.
