## 온프레미스 Git 서버 구축 및 원격 저장소 활용

온프레미스(On-premise) 환경에서 Git 서버를 구축한다는 것은 외부 서비스(GitHub, GitLab SaaS 등)를 사용하지 않고, 사내 서버나 개인 PC를 중앙 저장소로 만드는 것을 의미합니다. 단순히 Git을 설치하는 것을 넘어, 타인이 내 컴퓨터에 접근하여 데이터를 주고받을 수 있는 **통신 프로토콜(주로 SSH)** 설정이 핵심입니다.

---

### 1. Git 서버의 동작 원리

Git 서버는 실제로는 작업 디렉토리가 없는 **Bare Repository**를 통해 운영됩니다. 일반적인 프로젝트 폴더와 달리 소스 코드가 직접 보이지 않고, 버전 관리 데이터만 들어있는 형태입니다.

* **내 컴퓨터(서버):** `git init --bare` 명령어로 빈 저장소를 생성합니다.
* **타인의 컴퓨터(클라이언트):** `git clone ssh://사용자명@내IP/경로`를 통해 접속합니다.

---

### 2. 리눅스(Ubuntu) 기반 Git 서버 구축 단계

가장 안정적이고 보편적인 방식은 리눅스 서버에 SSH를 이용해 구축하는 방법입니다.

#### 1단계: Git 설치 및 사용자 생성

보안을 위해 Git 작업 전용 사용자를 생성하는 것이 좋습니다.

```bash
# Git 설치
sudo apt update
sudo apt install git-all

# git 관리 전용 유저 생성
sudo adduser git

```

#### 2단계: Bare 저장소 생성

프로젝트 데이터가 저장될 중앙 저장소를 만듭니다.

```bash
# git 유저로 전환
su - git

# 저장소 디렉토리 생성
mkdir my-project.git
cd my-project.git

# Bare 저장소 초기화
git init --bare

```

#### 3단계: SSH 접근 설정

타인이 내 서버에 접속하려면 해당 사용자의 `SSH Public Key`가 서버의 `~/.ssh/authorized_keys`에 등록되어 있어야 합니다.

---

### 3. 클라이언트에서 원격 저장소 연결 (Origin 설정)

서버 세팅이 끝났다면, 다른 사용자는 자신의 로컬 환경에서 다음과 같이 연결합니다.

#### 신규 프로젝트로 시작할 때

```bash
git clone git@서버IP:/home/git/my-project.git

```

#### 기존 로컬 프로젝트를 서버에 올릴 때

```bash
# 원격 저장소(origin) 등록
git remote add origin git@서버IP:/home/git/my-project.git

# 첫 푸시
git push -u origin main

```

---

### 4. 주의사항 및 환경별 고려사항

* **방화벽 설정:** 외부에서 접속하려면 서버의 **22번 포트(SSH)**가 열려 있어야 합니다.
* **IP 주소:** 서버의 IP가 유동 IP라면 접속 주소가 계속 바뀝니다. 고정 IP를 할당하거나 내부 DNS를 사용하는 것이 좋습니다.
* **GUI 인터페이스:** 명령어 기반 관리가 힘들다면 오픈소스인 **Gitea**나 **GitLab Self-managed** 설치를 권장합니다. 훨씬 직관적인 웹 UI를 제공합니다.

---

### 5. AWS 환경에서의 고려 (참고)

만약 온프레미스가 아닌 AWS EC2 등을 서버로 활용하신다면 다음 비용 발생 요소를 확인해야 합니다.

> **과금 주의 요소**
> * **EC2 Instance:** 프리티어(t2.micro 등) 범위를 초과하거나 장시간 구동 시 인스턴스 비용 발생.
> * **EBS Storage:** 저장소 용량에 따른 과금.
> * **Data Transfer Out:** 서버에서 외부(클라이언트)로 데이터를 보낼 때 데이터 전송 요금 발생.
