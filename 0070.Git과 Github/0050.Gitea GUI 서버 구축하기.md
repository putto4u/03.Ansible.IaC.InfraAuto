



### 다운로드 실행
```
wget -O gitea https://dl.gitea.com/gitea/1.25.3/gitea-1.25.3-linux-amd64

chmod +x gitea

```
## Gitea 초기 설정 및 기본 사용 가이드

```
./gitea web
``` 

실행 후 웹 브라우저 접속에 성공했다면, 서비스 운영을 위한 초기 구성 단계가 필요합니다. 가장 간편한 **SQLite** 방식을 기준으로 초기 설정과 기본 사용법을 안내합니다.

---

### 1. 웹 초기 설정 마법사 (First Run Configuration)

브라우저에서 `http://[서버IP]:3000`에 처음 접속하면 설정 페이지가 나타납니다. 다음 항목들을 입력하십시오.

#### 1.1 데이터베이스 설정

* **데이터베이스 유형:** `SQLite3` 선택 (가장 간편하며 별도 서버 설치가 필요 없음)
* **경로:** 기본값 유지 (보통 `data/gitea.db`)

#### 1.2 일반 설정

* **사이트 제목:** 원하는 이름 입력 (예: `My Git Service`)
* **저장소 최상위 경로:** 기본값 유지 (`/home/git/gitea-repositories` 등)
* **SSH 서버 포트:** `22` (이미 사용 중이라면 `2222` 등으로 변경 가능)
* **Gitea HTTP 포트:** `3000`
* **Gitea 기본 URL:** `http://[서버IP]:3000/` (실제 접속 주소와 일치해야 함)

#### 1.3 관리자 계정 설정 (중요)

설정 페이지 하단의 **[관리자 계정 설정]** 화살표를 눌러 관리자 정보를 입력합니다.

* **관리자 사용자 명:** 본인이 사용할 아이디 (예: `master`)
* **비밀번호:** 보안이 강화된 비밀번호
* **이메일 주소:** 본인 이메일

설정을 마치고 **[Gitea 설치하기]** 버튼을 누르면 잠시 후 메인 화면으로 이동합니다.

---

### 2. Gitea 기본 사용법

설치가 완료되면 GitHub와 매우 유사한 인터페이스를 통해 저장소를 관리할 수 있습니다.

#### 2.1 새로운 저장소(Repository) 만들기

1. 우측 상단의 **[+]** 버튼 클릭 후 **[새 저장소]** 선택.
2. **저장소 이름** 입력 (예: `my-project`).
3. **공개 여부** 선택 (Private 체크 시 나만 볼 수 있음).
4. **저장소 만들기** 클릭.

#### 2.2 로컬 프로젝트 연결 및 푸시(Push)

내 컴퓨터(로컬)에 있는 코드를 Gitea 서버로 올리는 방법입니다.

```bash
# 1. 로컬 저장소 초기화
git init

# 2. 원격 저장소(Gitea) 연결
git remote add origin http://[서버IP]:3000/[사용자ID]/my-project.git

# 3. 파일 추가 및 커밋
git add .
git commit -m "Initial commit"

# 4. 서버로 전송
git push origin main

```

#### 2.3 팀원 초대 및 조직 관리

* **조직(Organization):** 프로젝트 그룹을 만들어 여러 명의 팀원을 관리할 수 있습니다.
* **협업자(Collaborators):** 저장소 설정의 [협업자] 메뉴에서 다른 사용자를 추가하여 공동 작업이 가능합니다.

---

### 3. Gitea 서버 관리 팁

* **백업:** Gitea 실행 파일이 있는 폴더의 `data` 디렉터리와 `custom/conf/app.ini` 설정 파일만 잘 보관해도 전체 복구가 가능합니다.
* **업데이트:** 새로운 버전의 바이너리 파일을 다운로드한 뒤 기존 파일과 교체하고 재시작하면 자동으로 데이터베이스 스키마가 업데이트됩니다.

---

### 4. 서비스 과금 및 인프라 안내

* **네트워크 전송량:** `git push`나 `pull`을 수행할 때 클라우드 외부로 나가는 트래픽에 대해 **AWS Data Transfer Out** 비용이 발생할 수 있습니다. 다만, 소규모 텍스트 코드 위주의 작업은 프리티어 허용량 이내에서 처리가 가능합니다.
* **스토리지:** 저장소에 대용량 바이너리 파일을 많이 올릴 경우 **AWS EBS(디스크)** 사용량이 증가하여 비용이 발생할 수 있으니 주의하십시오.
