이미 특정 계정(예: 본인 계정)으로 SSH 키를 등록하여 통신하고 있었다면, **접속하려는 대상 계정이 누구냐**에 따라 키 등록 여부가 결정됩니다.

---

### 1. 핵심 원칙: SSH 키는 '서버의 계정'별로 관리됩니다.

SSH 접속은 `사용자명@IP주소` 형식을 사용합니다. 이때 서버는 접속을 요청한 사용자가 누구인지 확인하기 위해, 해당 사용자 홈 디렉토리 안에 있는 `authorized_keys` 파일을 확인합니다.

* **본인 계정(`user1`)으로 접속할 때:** `/home/user1/.ssh/authorized_keys` 확인
* **Git 계정(`git`)으로 접속할 때:** `/home/git/.ssh/authorized_keys` 확인

따라서 이전에 본인 계정에 키를 등록했더라도, 앞으로 **`git@IP주소`** 방식으로 접속하고 싶다면 **`git` 유저의 홈 디렉토리에 키를 다시 등록**해야 합니다.

---

### 2. 키 등록 및 이전 절차

만약 기존 계정에 등록된 키를 `git` 유저에게도 적용하고 싶다면, 파일을 복사하거나 내용을 추가해주면 됩니다.

#### 방법 A: 기존 키 내용 복사 (권장)

```bash
# git 유저의 .ssh 디렉토리 생성 (root 또는 sudo 권한 필요)
sudo mkdir -p /home/git/.ssh

# 기존 유저의 키 내용을 git 유저의 목록으로 복사
sudo cat /home/현재유저/.ssh/authorized_keys >> /home/git/.ssh/authorized_keys

# 소유권과 권한 설정 (중요: 권한이 틀리면 접속이 거부됨)
sudo chown -R git:git /home/git/.ssh
sudo chmod 700 /home/git/.ssh
sudo chmod 600 /home/git/.ssh/authorized_keys

```

#### 방법 B: 클라이언트에서 다시 전송

상대방(타인)의 컴퓨터에서 아래 명령어를 다시 실행하게 합니다.

```bash
ssh-copy-id git@서버IP

```

---

### 3. 클라이언트에서의 원격지 주소 수정

서버에서 키 설정을 마쳤다면, 협업자들은 기존에 등록된 `origin` 주소를 수정해야 `git` 유저로 접속할 수 있습니다.

```bash
# 기존 주소 확인
git remote -v

# 주소 변경 (기존 계정명에서 git으로 변경)
git remote set-url origin git@서버IP:/home/git/repo.git

```

---

### 4. 관리 효율성 측면

협업자가 많아질수록 각자의 개인 계정에 키를 등록하는 것보다, **`git`이라는 공용 계정 하나**의 `authorized_keys` 파일에 모든 협업자의 Public Key를 모아 관리하는 것이 훨씬 유지보수에 유리합니다. 퇴사나 협업 종료 시 해당 키만 삭제하면 접근을 즉시 차단할 수 있기 때문입니다.

---

### 5. 인프라 운영 참고 (AWS)

AWS EC2 환경에서 계정을 새로 만들고 키를 관리할 때 다음 사항을 유의하세요.

> **과금 및 운영 주의**
> * **Elastic IP:** 서버 IP가 바뀌면 모든 클라이언트의 `origin` 주소를 다시 수정해야 합니다. 고정 IP(EIP)를 사용하면 편리하지만, 인스턴스에 연결되지 않은 상태로 방치하면 소액의 비용이 발생합니다.
> * **Security Group:** 어떤 유저로 접속하든 상관없이 **TCP 22번 포트**는 항상 허용되어 있어야 합니다.
