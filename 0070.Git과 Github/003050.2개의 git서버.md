두 디렉토리가 서로 다른 Git 서버(하나는 GitHub, 하나는 사내 Git 서버)를 바라보고 있을 때, 가장 주의해야 할 핵심은 **"자아(Identity)의 분리"**와 **"인증(Authentication)의 충돌 방지"**입니다.

이 두 가지를 제대로 설정하지 않으면 사내 프로젝트에 개인 이메일로 커밋이 남거나, 권한 문제로 접속이 거부되는 상황이 발생합니다. 다음은 전문가처럼 이 환경을 세팅하기 위한 체크리스트입니다.

---

### 1. 자아 분리 (User Identity Separation)

가장 흔한 실수는 회사 코드에 `personal@gmail.com`으로 커밋을 남기는 것입니다. 이를 방지하기 위해 **전역(Global) 설정**과 **지역(Local) 설정**을 명확히 구분해야 합니다.

* **문제점:** `git config --global user.email` 하나만 설정해두면, 회사 프로젝트에서도 개인 이메일이 사용됩니다.
* **해결책 (수동 설정):** 회사 프로젝트 디렉토리 안에서만 별도로 지역 설정을 덮어씌웁니다.
```bash
# 회사 프로젝트 폴더로 이동 후 실행
git config user.name "Your Name (Company)"
git config user.email "name@company.com"

```


* **해결책 (자동화 - 추천):** 특정 폴더 경로에 따라 설정을 자동 변경하는 `includeIf` 기능을 사용합니다 (Git 2.13+).
* `~/.gitconfig` (전역 설정 파일)에 다음 내용을 추가:
```ini
[includeIf "gitdir:~/company-projects/"]
    path = .gitconfig-company

```


* `~/.gitconfig-company` 파일을 새로 만들고 회사용 이메일 설정 저장.



### 2. 인증 키 분리 (SSH Key Management)

GitHub와 사내 서버가 모두 SSH를 사용한다면, **서로 다른 SSH 키**를 사용해야 보안상 안전하고 관리하기 쉽습니다.

* **주의할 점:** 기본적으로 Git은 `~/.ssh/id_rsa` 하나만 찾으려 합니다. 두 서버가 다른 키를 요구할 때 충돌이 납니다.
* **해결책:** `~/.ssh/config` 파일을 작성하여 서버별로 사용할 키를 지정해 줍니다.
```ssh
# ~/.ssh/config 예시

# GitHub (개인용)
Host github.com
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_rsa_personal

# 회사 Git 서버
Host git.company.com
  HostName git.company.com
  User git
  IdentityFile ~/.ssh/id_rsa_company

```



### 3. 네트워크 및 보안 설정

사내 Git 서버는 보통 보안이 더 엄격합니다.

* **VPN 필수 여부:** 사내 서버는 사내망(Intranet)이나 VPN 연결 상태에서만 접속되도록 설정된 경우가 많습니다. 집에서 작업 시 접속이 안 된다면 VPN 연결을 먼저 확인해야 합니다.
* **HTTP vs SSH 포트:** 회사 방화벽 정책에 따라 표준 SSH 포트(22)가 막혀있고 별도의 포트(예: 2222)를 써야 할 수도 있습니다. 이 경우 `clone` 주소가 `ssh://git@server:2222/repo.git` 형태가 됩니다.

### 4. 실수 방지 팁

커밋하기 전에 현재 내가 어떤 계정으로 설정되어 있는지 확인하는 습관을 들이세요.

```bash
git config user.email
# 출력 결과가 현재 저장소에 맞는 이메일인지 확인

```
