## SSH 키 관리 및 보안 운영 전략

온프레미스 Git 서버를 운영할 때 가장 중요한 자산은 소스 코드이며, 그 문지기 역할을 하는 것이 바로 **SSH 키(SSH Key)**입니다. 여러 사용자가 참여하는 환경에서 키를 체계적으로 관리하지 않으면 보안 사고로 이어질 수 있습니다.

---

### 1. SSH 키 관리의 핵심: `authorized_keys`

서버의 `git` 유저 홈 디렉토리에는 `.ssh/authorized_keys`라는 파일이 있습니다. 이 파일은 서버에 접속을 허용할 클라이언트들의 **공개키(Public Key)** 목록을 담고 있는 장부와 같습니다.

* **파일 위치:** `/home/git/.ssh/authorized_keys`
* **관리 방식:** 한 줄에 하나의 공개키(`ssh-rsa AAA...`)를 입력합니다.
* **보안 규칙:** 이 파일은 반드시 `git` 유저만 읽고 쓸 수 있어야 합니다. (권한 `600`)

---

### 2. 다중 사용자 환경에서의 키 등록 프로세스

협업자가 늘어날 때마다 다음의 표준 절차를 따르는 것이 안전합니다.

1. **키 생성 (클라이언트):** 협업자가 자신의 PC에서 `ssh-keygen -t rsa -b 4096` 명령으로 키 쌍을 생성합니다.
2. **공개키 수집:** 협업자로부터 `.pub` 확장자로 끝나는 **공개키** 파일만 전달받습니다. (**비밀키(.pem, id_rsa)는 절대 받으면 안 됩니다.**)
3. **서버 등록:** 전달받은 키의 내용을 `authorized_keys` 파일 하단에 추가합니다.
```bash
cat collaborator_key.pub >> /home/git/.ssh/authorized_keys

```



---

### 3. 보안 강화를 위한 접근 제한 (git-shell)

기본적으로 SSH 접속이 허용되면 서버의 쉘(Shell)에 접속하여 다른 명령어를 실행할 수 있습니다. 이를 방지하기 위해 `git` 유저의 로그인 쉘을 `git-shell`로 제한해야 합니다.

* **설정 방법:** `/etc/passwd` 파일에서 `git` 유저의 쉘 경로를 변경합니다.
```bash
# 변경 전: /bin/bash
# 변경 후: /usr/bin/git-shell
sudo chsh -s /usr/bin/git-shell git

```


* **효과:** 이제 이 계정으로 SSH 접속을 하면 Git 관련 명령어(push, pull)만 실행 가능하며, 일반적인 리눅스 명령어 사용은 차단됩니다.

---

### 4. 키 분실 및 폐기 관리

협업자가 퇴사하거나 노트북을 분실했을 경우, 즉시 접근 권한을 회수해야 합니다.

* **권한 회수:** `authorized_keys` 파일에서 해당 사용자의 공개키가 포함된 라인을 삭제하면 즉시 접속이 차단됩니다.
* **주기적 갱신:** 보안 정책에 따라 6개월~1년 단위로 키를 새로 생성하여 교체하는 것을 권장합니다.

---

### 5. AWS 환경에서의 관리 포인트

온프레미스가 아닌 AWS EC2를 Git 서버로 활용할 경우 추가적인 관리 요소가 있습니다.

| 관리 항목 | 설명 | 과금/주의사항 |
| --- | --- | --- |
| **Key Pairs** | 인스턴스 생성 시 부여되는 키 | 초기 접속용으로만 쓰고, 협업자 키는 위 방식대로 별도 관리 권장 |
| **Security Group** | 포트 기반 제어 | 특정 협업자의 IP만 22번 포트에 접속 가능하도록 화이트리스트 운영 |
| **IAM User** | AWS 콘솔 접근 권한 | Git 서버 내부의 SSH 키 관리와는 별개이며, 인스턴스 관리자에게만 부여 |

> **과금 주의**
> * **AWS KMS (Key Management Service):** 키를 암호화하여 안전하게 보관하는 서비스를 별도로 사용할 경우, 키 생성 및 호출 횟수에 따라 매월 소액의 비용($1/month + 사용량)이 발생할 수 있습니다. 단순 Git 서버 운영 시에는 파일 시스템 직접 관리가 가장 저렴합니다.
