Gitea와 같은 GUI 도구 없이, 리눅스 서버 자체의 기능을 활용하여 **순수 Git 서버(Bare Repository)**를 구축하는 방법입니다. 이 방식은 가볍고 빠르며, SSH 프로토콜을 기반으로 하므로 보안성이 뛰어납니다.

---

### 1. Git 서버 환경 구성

#### 1.1 서버측 Git 설치 및 사용자 생성

먼저 서버에 Git을 설치하고, Git 서비스를 전용으로 관리할 `git` 계정을 생성합니다.

```bash
# 1. 패키지 업데이트 및 Git 설치
sudo apt update
sudo apt install -y git

# 2. git 관리용 유저 생성 (비밀번호 설정 포함)
sudo adduser git

```

#### 1.2 SSH 인증 설정

매번 비밀번호를 입력하지 않도록 클라이언트의 SSH 공개키(`id_ed25519.pub` 등)를 서버의 `git` 유저 홈 디렉토리에 등록합니다.

```bash
# 서버의 git 유저로 전환
sudo su - git

# SSH 디렉토리 생성 및 권한 설정
mkdir .ssh
chmod 700 .ssh
touch .ssh/authorized_keys
chmod 600 .ssh/authorized_keys

# (클라이언트에서 복사해온 공개키 내용을 authorized_keys에 붙여넣기)
# 예: echo "ssh-ed25519 AAA..." >> ~/.ssh/authorized_keys

```

---

### 2. Bare 저장소 생성

Git 서버에는 작업 디렉토리가 없는 **Bare 저장소**를 생성해야 합니다. Bare 저장소는 파일 수정은 불가능하며, 오직 푸시(Push)된 이력 데이터만 보관합니다.

```bash
# 저장소를 모아둘 디렉토리 생성
mkdir ~/repos
cd ~/repos

# 'project.git'이라는 이름으로 Bare 저장소 초기화
git init --bare project.git

```

> **AWS 과금 주의**: 순수 Git 서버는 리소스를 거의 차지하지 않지만, EBS 저장 용량이 늘어나거나 데이터 전송량이 많아지면 과금이 발생할 수 있습니다. 특히 프리티어 인스턴스의 경우 트래픽 사용량을 모니터링하세요.

---

### 3. 클라이언트에서 서버 연결 및 사용

이제 로컬 PC에서 방금 만든 서버의 저장소를 원격지로 등록하고 사용합니다.

#### 3.1 원격 저장소 연결

로컬 작업 디렉토리에서 서버 주소를 등록합니다.

```bash
# 서버 IP와 생성한 경로를 입력 (SSH 방식)
git remote add origin git@서버_IP:/home/git/repos/project.git

```

#### 3.2 소스코드 푸시 (Push)

```bash
git add .
git commit -m "Initial commit"
git push origin main

```

#### 3.3 다른 환경에서 복제 (Clone)

```bash
git clone git@서버_IP:/home/git/repos/project.git

```

---

### 4. 운영 시 고려사항

| 구분 | 설명 |
| --- | --- |
| **보안** | `git` 유저의 쉘 접근을 제한하려면 `/etc/passwd`에서 쉘을 `git-shell`로 변경하십시오. |
| **권한 관리** | 순수 Git 서버는 팀원별 세부 권한(Read/Write) 관리가 어렵습니다. 모든 사용자가 SSH 키를 공유해야 합니다. |
| **백업** | `/home/git/repos` 디렉토리 전체를 주기적으로 백업하는 것이 중요합니다. |
