# Chapter 4. Linux 기반 프라이빗 Git 서버 구축 및 보안 설정

본 장에서는 GitHub와 같은 외부 호스팅 서비스를 사용하지 않고, 사내망 또는 개인 서버(Linux)에 직접 **보안이 강화된 Git 서버**를 구축하는 전체 과정을 다룬다. 앞서 논의된 '설치 시 주의사항(계정 분리, 셸 제한)'이 실제 구축 단계에 어떻게 적용되는지 중점적으로 기술한다.

---

### 1. 사전 환경 준비 및 패키지 설치

Git 서버 구축의 첫 단계는 패키지 설치다. 최신 보안 패치가 적용된 버전을 사용하기 위해 패키지 목록을 업데이트한 후 설치를 진행한다.

**명령어 (Ubuntu/Debian 기준):**

```bash
# 1. 패키지 리스트 업데이트
sudo apt-get update

# 2. Git 패키지 설치
sudo apt-get install git

# 3. 설치 버전 확인 (2.x 버전 이상 권장)
git --version

```

---

### 2. [보안 핵심] Git 서비스 전용 계정 생성

서버의 관리자(root) 계정이나 개인 사용자 계정을 Git 운영에 사용하는 것은 보안상 취약하다. **시스템 접근 권한을 최소화**하기 위해 Git 서비스만을 담당하는 격리된 계정을 생성한다.

**설정 절차:**

1. **계정 생성:** 홈 디렉토리를 포함하되, 비밀번호 로그인은 비활성화하여 생성한다.
2. **보안 옵션:** `--system` (시스템 계정), `--disabled-password` (비밀번호 없음) 옵션을 사용한다.

```bash
# git이라는 이름의 사용자 생성 (/home/git 홈 디렉토리 자동 생성)
sudo adduser --system --shell /bin/bash --group --disabled-password --home /home/git git

```

> **[Expert Note] 왜 비밀번호를 비활성화하는가?**
> Git 서버는 SSH Key 기반 인증을 표준으로 사용한다. 비밀번호 인증을 열어둘 경우 Brute Force(무차별 대입) 공격에 노출될 수 있으므로, 생성 단계에서부터 비밀번호를 설정하지 않는 것이 안전하다.

### 3. SSH 인증 환경 구성 (Authorized Keys)

클라이언트(개발자)가 서버에 접속하기 위한 SSH 키 저장소를 구성한다. 이 단계는 `git` 계정 권한으로 수행하거나, `root`에서 수행 후 소유권을 변경해야 한다.

**설정 절차:**

```bash
# 1. git 계정으로 전환
sudo su - git

# 2. SSH 설정 디렉토리 생성 및 권한 설정 (매우 중요)
mkdir .ssh && chmod 700 .ssh

# 3. 인증키 파일 생성
touch .ssh/authorized_keys && chmod 600 .ssh/authorized_keys

# 4. (예시) 개발자의 공개키(id_rsa.pub) 등록
# 실제 운영 시에는 개발자의 공개키 내용을 이 파일에 붙여넣기 한다.
echo "ssh-ed25519 AAAAC3NzaC... user@laptop" >> .ssh/authorized_keys

```

### 4. Bare Repository 생성 및 권한 설정

실제 소스 코드가 저장될 중앙 저장소를 생성한다. 이곳은 작업 디렉토리가 없는 순수 데이터베이스 형태인 **Bare Repository**로 만들어야 한다.

**설정 절차:**

1. 관례적으로 `/srv/git` 또는 `git` 계정의 홈 디렉토리 하위에 저장소를 둔다.
2. 반드시 `--bare` 옵션을 사용한다.

```bash
# 1. 프로젝트 디렉토리 생성 (관례상 .git 확장자 사용)
cd /home/git
mkdir project.git

# 2. Bare 저장소 초기화
cd project.git
git init --bare

# 3. [중요] 올바른 소유권 확인
# 만약 root 권한으로 생성했다면 소유권을 git 계정으로 반드시 변경해야 한다.
# (git 계정으로 로그인한 상태라면 생략 가능)
exit # 다시 root 또는 관리자 계정으로 복귀
sudo chown -R git:git /home/git/project.git

```

### 5. [보안 핵심] 로그인 셸 제한 (Git-Shell)

이 단계가 **설치 시 가장 주의해야 할 보안 설정**이다. `git` 계정으로 로그인한 사용자가 서버의 일반 셸 프롬프트(bash 등)를 획득하지 못하도록 막고, 오직 Git 관련 명령어(push, pull)만 수행할 수 있도록 제한한다.

**설정 절차:**

1. **git-shell 경로 확인:**
```bash
which git-shell
# 출력 예시: /usr/bin/git-shell

```


2. **유효한 셸 목록에 추가:**
`/etc/shells` 파일에 `git-shell` 경로가 없다면 추가해준다. (보안 정책상 등록되지 않은 셸은 접속이 거부될 수 있음)
```bash
# /etc/shells 파일 끝에 경로 추가
sudo sh -c "echo $(which git-shell) >> /etc/shells"

```


3. **계정 셸 변경:**
`git` 계정의 기본 셸을 `bash`에서 `git-shell`로 변경한다.
```bash
sudo chsh git -s $(which git-shell)

```



**보안 검증:**
이제 터미널에서 `ssh git@<서버IP>` 명령어로 접속을 시도하면 다음과 같은 메시지와 함께 연결이 닫혀야 정상이다.

> *fatal: Interactive git shell is not enabled.*
> *hint: ~/git-shell-commands should exist and have read and execute access.*
> *(Connection to server closed.)*

### 6. 클라이언트 접속 테스트

모든 설정이 완료되었으므로 개발자 PC(클라이언트)에서 원격 저장소 복제를 시도한다.

```bash
# 클라이언트(내 PC)에서 실행
# 형식: git clone [계정]@[서버IP]:[저장소경로]
git clone git@192.168.0.50:/home/git/project.git

```

* **성공 시:** 빈 저장소를 복제했다는 메시지(`warning: You appear to have cloned an empty repository.`)가 뜨며 폴더가 생성된다.
* **실패 시:** `Permission denied`가 뜬다면 SSH Key 등록 여부(`authorized_keys`)와 파일 권한을 재확인한다.
