## 앤서블(Ansible): 자동화의 시작과 효율적인 인프라 관리

### 1. 앤서블(Ansible)이란 무엇인가?

앤서블은 서버의 설정, 소프트웨어 배포, 서비스 오케스트레이션 등을 자동화하는 오픈소스 IT 자동화 도구입니다. 복잡한 IT 환경을 코드로 관리할 수 있게 해주며, 특히 **'에이전트리스(Agentless)'** 방식이라는 독보적인 특징 덕분에 현대 인프라 관리의 필수 도구로 자리 잡았습니다.

#### 앤서블의 3대 핵심 철학

1. **단순함 (Simple):** 인간이 읽기 쉬운 YAML 언어를 사용하여 누구나 쉽게 배우고 작성할 수 있습니다.
2. **강력함 (Powerful):** 복잡한 워크플로우를 조율하고, 애플리케이션 배포부터 네트워크 설정까지 전 과정을 자동화합니다.
3. **안전함 (Agentless):** 관리 대상 서버에 별도의 소프트웨어(에이전트)를 설치할 필요가 없어 보안상 유리하고 리소스 낭비가 적습니다.

---

### 2. 왜 앤서블인가? (주요 특징과 장점)

#### 에이전트리스(Agentless) 방식

기존의 다른 자동화 도구들은 관리 대상 서버마다 특정 프로그램을 미리 설치해야 했습니다. 하지만 앤서블은 표준 보안 프로토콜인 **SSH** (또는 Windows의 WinRM)를 그대로 사용합니다.

* **이점:** 관리가 간편하고, 보안 정책을 준수하기 쉬우며, 관리 대상 서버의 성능에 영향을 주지 않습니다.

#### 멱등성 (Idempotency)

여러 번 실행해도 결과가 항상 같음을 보장하는 성질입니다.

* **예시:** "A 패키지를 설치하라"는 명령을 10번 실행해도, 이미 설치되어 있다면 앤서블은 아무 작업도 하지 않고 'OK'를 반환합니다. 이 덕분에 시스템 상태를 의도한 대로 안전하게 유지할 수 있습니다.

#### 푸시 기반 구조 (Push-based)

중앙의 관리 컴퓨터(Control Node)에서 대상 서버(Managed Node)로 설정 내용을 밀어넣는 방식입니다. 변경 사항을 즉각적으로 적용할 수 있다는 장점이 있습니다.

---

### 3. 앤서블의 구성 요소

앤서블을 다루기 위해 반드시 알아야 할 4가지 개념입니다.

1. **제어 노드 (Control Node):** 앤서블이 설치되어 명령을 내리는 컴퓨터입니다. (주로 리눅스/맥 환경)
2. **관리 대상 노드 (Managed Node):** 앤서블로 관리되는 서버나 네트워크 장비들입니다.
3. **인벤토리 (Inventory):** 관리 대상 노드들의 리스트를 담은 파일입니다. IP 주소나 그룹명으로 서버들을 분류합니다.
4. **플레이북 (Playbook):** "무엇을 할 것인가"를 정의한 일종의 자동화 시나리오입니다. YAML 형식으로 작성됩니다.

### 4. 앤서블 실무 맛보기: 플레이북 작성

플레이북은 앤서블의 꽃입니다. 아래는 웹 서버(Nginx)를 설치하고 실행하는 아주 간단한 예시입니다.

* deploy_web.yml

```yaml
---
- name: 웹 서버 설치 시나리오
  hosts: webservers  # 인벤토리에 정의된 그룹명
  become: true       # 관리자 권한(sudo)으로 실행

  tasks:
    - name: Nginx 패키지가 설치되어 있는지 확인
      apt:           # 데비안/우분투용 패키지 관리 모듈
        name: nginx
        state: present

    - name: Nginx 서비스를 시작함
      service:
        name: nginx
        state: started
        enabled: yes

```

* inventory.ini 호스트 등록 및 그룹화
```
[webservers]
# 실제 AWS/클라우드 서버의 IP 주소 또는 호스트명을 입력합니다.
web_server_1 ansible_host=192.168.1.10
web_server_2 ansible_host=192.168.1.11

[all:vars]
# 모든 호스트에 적용될 변수 (ssh 접속 계정)
ansible_user=ubuntu
```


```
# Ansible 실행 명령어
ansible-playbook -i inventory.ini deploy_web.yml
```

### 💡 전문 용어 해설 (코멘트)

* **오케스트레이션 (Orchestration):** 여러 대의 서버나 복잡한 서비스들이 조화롭게 작동하도록 순서에 맞게 자동화하고 관리하는 것을 말합니다. 마치 지휘자가 오케스트라를 지휘하는 것과 같습니다.
* **YAML (YAML Ain't Markup Language):** 데이터를 구조화해서 표현하기 위한 양식입니다. "키: 값" 형태로 이루어져 있어 프로그래밍을 모르는 사람도 쉽게 읽을 수 있습니다.
* **SSH (Secure Shell):** 네트워크상의 다른 컴퓨터에 로그인하거나 명령을 실행할 수 있게 해주는 암호화된 통신 규약입니다.
* **모듈 (Module):** 앤서블이 실제로 작업을 수행하는 작은 프로그램 단위입니다. (예: 파일 복사 모듈, 패키지 설치 모듈 등)

### 5. 실전 팁 및 주의사항

* **버전 관리 시스템(Git) 활용:** 플레이북은 '코드'입니다. 반드시 Git과 같은 도구로 버전을 관리하여 누가, 언제 인프라 설정을 바꿨는지 추적하세요.
* **Ansible Galaxy 활용:** 전 세계 전문가들이 미리 만들어 둔 플레이북 저장소인 [Ansible Galaxy](https://galaxy.ansible.com/)를 참고하면 처음부터 고생하며 코드를 짤 필요가 없습니다.
* **가독성 우선:** 플레이북의 `name` 항목에는 이 작업이 무엇을 하는지 아주 구체적으로 적으세요. 나중에 동료나 미래의 자신이 코드를 볼 때 큰 도움이 됩니다.
