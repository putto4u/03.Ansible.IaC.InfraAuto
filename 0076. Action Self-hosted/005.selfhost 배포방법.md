## Self-hosted Runner를 활용한 지속적 배포(CD) 전략

Self-hosted Runner는 대상 서버(배포 타겟)에 직접 설치되어 실행되므로, 외부로 포트를 개방하거나 복잡한 SSH 키 관리 없이도 내부 리소스에 직접 접근하여 안전하고 빠르게 배포를 수행할 수 있는 장점이 있습니다.

---

### 1. 배포 아키텍처 및 방식

Self-hosted Runner를 통한 CD는 크게 두 가지 방식으로 구현됩니다.

* **직접 배포 (Agent-based)**: 애플리케이션이 구동될 서버 자체에 Runner를 설치합니다. 워크플로우 실행 시 로컬 디렉토리에서 빌드 후 바로 프로세스를 재시작합니다.
* **브릿지 배포 (Jump-host)**: 별도의 관리용 서버에 Runner를 설치하고, 이 서버가 동일 네트워크(VPC) 내의 다른 EC2 인스턴스들에 배포 명령을 전달합니다.

---

### 2. 단계별 배포 워크플로우 예제

이 예제는 코드가 푸시되면 Runner가 설치된 서버에서 최신 코드를 받고, 서비스를 재시작하는 가장 표준적인 CD 구성입니다.

**파일명:** `.github/workflows/deploy.yml`

```yaml
name: Continuous-Deployment

on:
  push:
    branches: [ "main" ]

jobs:
  deploy:
    # 1. 자체 호스팅 러너 지정
    runs-on: self-hosted

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Install dependencies
        run: |
          npm install
          # 또는 Python: pip install -r requirements.txt

      - name: Build application
        run: |
          npm run build

      - name: Restart Service
        run: |
          # PM2나 systemd를 사용하여 서비스 재시작
          pm2 restart my-app || pm2 start dist/main.js --name my-app
          # 또는 sudo systemctl restart my-service

```

---

### 3. 주요 설정 팁

* **권한 설정**: Runner가 서비스를 재시작(`systemctl restart`)하거나 특정 폴더에 쓸 권한이 있어야 합니다. 필요 시 `sudoers` 설정을 통해 특정 명령어만 패스워드 없이 실행 가능하도록 설정합니다.
* **환경 변수 관리**: 서버 로컬의 `.env` 파일을 직접 참조하거나, GitHub Secrets를 통해 배포 시점에 파일을 생성하도록 구성합니다.
* **서비스화**: Runner가 서버 재부팅 후에도 자동으로 실행되도록 `svc.sh` 스크립트를 사용하여 시스템 서비스로 등록해야 합니다.
```bash
sudo ./svc.sh install
sudo ./svc.sh start

```

### 4. AWS 유료 서비스 및 과금 주의사항

Self-hosted CD 환경 구축 시 발생하는 비용 요소입니다.

* **EC2 Compute 요금 (유료)**: 배포 대상 또는 Runner 전용 인스턴스가 가동되는 시간에 비례하여 **인스턴스 타입별 요금**이 청구됩니다. 24시간 가동되는 CD 서버라면 **예약 인스턴스(RI)나 Savings Plans** 적용을 고려해야 합니다.
* **EBS 처리량 및 용량 (유료)**: 빈번한 빌드와 배포가 일어날 경우 EBS의 IOPS 및 처리량 비용이 발생할 수 있습니다. 특히 **gp3 볼륨**의 기본 성능을 초과하는 설정 시 추가 과금됩니다.
* **VPC 데이터 전송 (유료)**: 만약 Runner 서버와 배포 대상 서버가 서로 다른 가용 영역(AZ)에 위치한다면, **가용 영역 간 데이터 전송 요금($0.01/GB)**이 발생합니다. 동일 AZ에 배치하는 것이 비용 절감에 유리합니다.
* **NAT Gateway 데이터 처리 (유료 주의)**: 프라이빗 서브넷의 Runner가 GitHub API와 통신하기 위해 NAT Gateway를 통과할 때, 배포 시 발생하는 대용량 패키지 다운로드 등으로 인해 **데이터 처리 요금($0.045/GB)**이 누적될 수 있습니다.
