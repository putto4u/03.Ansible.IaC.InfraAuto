## GitHub Actions 기반 CD 배포 실습 과제 10선

Self-hosted Runner와 GitHub-hosted Runner를 활용하여 다양한 환경에 애플리케이션을 배포하는 실습 과정입니다. 기초적인 파일 전송부터 무중단 배포까지 난이도 순으로 구성했습니다.

---

### [Level 1: 기초 파일 배포]

#### 1. 로컬 디렉토리 동기화 (S3)

* **목표**: 빌드된 정적 파일을 클라우드 스토리지에 업로드합니다.
* **답안**: `aws s3 sync ./dist s3://my-bucket`
* **설명**: 가장 기본적인 CD의 형태로, 정적 웹사이트 배포에 주로 쓰입니다.

#### 2. SSH를 이용한 원격 서버 파일 전송 (SCP)

* **목표**: 특정 서버의 지정된 경로로 파일을 복사합니다.
* **답안**: `appleboy/scp-action` 등을 사용하여 `.tar.gz` 파일을 전송합니다.
* **설명**: 클라우드 에이전트 없이 기존 레거시 서버에 배포할 때 사용합니다.

---

### [Level 2: 프로세스 제어 및 환경 설정]

#### 3. Self-hosted Runner 기반 프로세스 재시작

* **목표**: 서버 내에서 직접 코드를 수정하고 서비스를 재구동합니다.
* **모범 답안**:

```yaml
- name: Deploy and Restart
  run: |
    git pull origin main
    npm install
    pm2 restart app-name # PM2를 통한 프로세스 재시작

```

* **설명**: Runner가 배포 대상 서버에 설치되어 있어 별도의 인증 없이 로컬 명령어로 배포합니다.

#### 4. 환경 변수(.env) 동적 생성

* **목표**: 보안이 필요한 설정 파일을 배포 시점에 주입합니다.
* **답안**: `echo "${{ secrets.ENV_FILE }}" > .env`
* **설명**: 코드에 포함되면 안 되는 DB 접속 정보 등을 GitHub Secrets에서 가져와 생성합니다.

---

### [Level 3: 컨테이너 배포]

#### 5. Docker Compose를 이용한 다중 컨테이너 배포

* **목표**: 여러 서비스(App, DB)를 한 번에 업데이트합니다.
* **답안**: `docker-compose up -d --build`
* **설명**: 컨테이너 기반 환경에서 가장 대중적인 배포 방식입니다.

#### 6. AWS ECR 이미지 푸시 및 ECS 서비스 업데이트

* **목표**: 관리형 컨테이너 서비스에 새 이미지를 배포합니다.
* **답안**: `aws ecs update-service --cluster my-cluster --service my-service --force-new-deployment`
* **설명**: AWS 인프라를 활용한 전문적인 컨테이너 오케스트레이션 배포입니다.
* **과금 주의**: **ECR 저장 비용(월 $0.10/GB)** 및 **ECS Fargate 실행 비용**이 발생합니다.

---

### [Level 4: 서버리스 및 고급 배포]

#### 7. AWS Lambda 함수 코드 업데이트

* **목표**: 서버리스 함수의 로직을 실시간으로 변경합니다.
* **답안**: `aws lambda update-function-code --function-name my-func --zip-file fileb://deploy.zip`
* **설명**: 서버 관리 부담이 없는 서버리스 환경의 CD를 익힙니다.
* **과금 주의**: **Lambda 호출 횟수 및 실행 시간**에 따라 비용이 발생합니다.

#### 8. Terraform을 이용한 인프라 자동 변경 (IaC CD)

* **목표**: 코드 변경 시 AWS 인프라 구조 자체가 변경되도록 합니다.
* **답안**: `terraform apply -auto-approve`
* **설명**: 애플리케이션뿐만 아니라 인프라 자체의 변경을 자동화합니다.
* **과금 주의**: 실수로 고사양 리소스를 생성할 경우 **즉시 유료 과금**되므로 주의가 필요합니다.

---

### [Level 5: 무중단 및 자동화 완성]

#### 9. Blue-Green 배포 (슬롯 교체 방식)

* **목표**: 서비스 중단 없이 신규 버전을 배포합니다.
* **설명**: 새 버전(Green)을 완벽히 띄운 후 로드밸런서의 타겟 그룹을 교체합니다.
* **과금 주의**: 배포 순간에 **두 배의 리소스(EC2 등)**를 사용하므로 일시적으로 비용이 증가합니다.

#### 10. 배포 실패 시 자동 롤백 (Rollback)

* **목표**: 배포 후 헬스 체크 실패 시 이전 버전으로 즉시 되돌립니다.
* **모범 답안**:

```yaml
- name: Health Check
  run: |
    status_code=$(curl -o /dev/null -s -w "%{http_code}" http://localhost:8080/health)
    if [ $status_code -ne 200 ]; then
      echo "Deployment failed! Rolling back..."
      # 이전 버전으로 되돌리는 스크립트 실행
      exit 1
    fi

```

* **설명**: 배포의 안정성을 보장하는 가장 높은 수준의 자동화 단계입니다.

---

### 핵심 과금 요소 요약 (AWS)

| 서비스 | 과금 포인트 | 비고 |
| --- | --- | --- |
| **EC2** | 인스턴스 가동 시간 | t3.micro 등 프리티어 적극 활용 권장 |
| **NAT Gateway** | 데이터 처리량 ($0.045/GB) | 프라이빗 서브넷 배포 시 주의 |
| **S3 / ECR** | 데이터 저장 및 전송량 | 실습 후 데이터 삭제 필수 |
| **Data Transfer** | 리전 외 데이터 전송 | GB당 약 $0.09 ~ $0.12 발생 |
