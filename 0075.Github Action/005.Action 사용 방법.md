## GitHub Actions 실습: 간단한 배포 워크플로우 예제

GitHub Actions의 실제 사용법을 익히기 위해, 코드가 `main` 브랜치에 푸시될 때마다 간단한 메시지를 출력하고 AWS S3로 정적 파일을 동기화하는 예제 시나리오를 살펴보겠습니다.

---

### 1. 워크플로우 파일 생성

모든 GitHub Actions 설정은 프로젝트 루트 디렉토리의 `.github/workflows/` 폴더 안에 YAML 파일로 저장되어야 합니다.

**파일명:** `.github/workflows/hello-actions.yml`

```yaml
name: CI-CD-Example

# 1. 트리거 조건 설정 (main 브랜치에 push 발생 시)
on:
  push:
    branches: [ "main" ]

jobs:
  # 2. 작업 정의
  build-and-deploy:
    runs-on: ubuntu-latest # 실행 환경 (GitHub 호스팅 러너)

    steps:
      # 3. 소스 코드 체크아웃
      - name: Checkout code
        uses: actions/checkout@v4

      # 4. 단순 스크립트 실행
      - name: Run a one-line script
        run: echo "Hello, GitHub Actions!"

      # 5. AWS S3 동기화 (AWS 인증 정보 필요)
      - name: Deploy to S3
        run: |
          echo "Deploying to AWS S3..."
          # aws s3 sync . s3://my-bucket-name

```

---

### 2. 주요 구성 요소 설명

1. **`on`**: 워크플로우를 언제 실행할지 정의합니다. 위 예제는 `main` 브랜치에 코드가 올라올 때마다 실행됩니다.
2. **`jobs`**: 하나의 워크플로우 안에서 수행될 작업 단위입니다. `runs-on: ubuntu-latest`는 가상 서버(Ubuntu)를 빌려 사용하겠다는 의미입니다.
3. **`uses`**: 다른 사람이 이미 만들어 놓은 Action을 가져다 씁니다. `actions/checkout`은 내 저장소의 코드를 가상 서버로 내려받는 필수 액션입니다.
4. **`run`**: 터미널에서 실행할 명령어를 직접 입력합니다.

---

### 3. AWS 서비스 연동 및 과금 주의사항

GitHub Actions를 통해 AWS 인프라를 핸들링할 때 반드시 다음 사항을 체크해야 합니다.

* **S3 스토리지 비용 (유료)**: `aws s3 sync` 명령어를 통해 파일을 업로드하면, S3에 저장되는 **데이터 용량**과 **PUT 요청 횟수**에 따라 비용이 발생합니다.
* **AWS CLI 호출**: GitHub 호스팅 러너에는 기본적으로 AWS CLI가 설치되어 있습니다. CLI 호출 자체는 무료이나, 이를 통해 제어하는 서비스(EC2, S3, RDS 등)는 **AWS 리소스 요금**이 청구됩니다.
* **GitHub Actions 분당 과금 (유료 전환)**:
* 위 예제처럼 `ubuntu-latest`를 사용하는 경우, 프라이빗 저장소는 월 2,000분까지만 무료입니다.
* 복잡한 빌드 작업으로 인해 실행 시간이 길어지면 무료 한도를 소진하고 **분당 $0.008** 이상의 비용이 발생할 수 있습니다.


* **Identity Provider (OIDC) 사용 권장**: AWS Access Key를 직접 입력하는 대신 IAM Identity Center를 통한 OIDC 방식을 쓰면 보안성이 높아지며, 이 인증 설정 자체는 무료입니다.
