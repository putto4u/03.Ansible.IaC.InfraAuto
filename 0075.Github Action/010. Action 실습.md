## GitHub Actions 단계별 실습 모범 답안 및 가이드

각 레벨의 대표적인 실습 과제에 대한 YAML 구성 요소와 실행 방법을 정리했습니다. 이 가이드는 프로젝트 루트의 `.github/workflows/` 디렉토리에 저장하여 바로 테스트할 수 있도록 작성되었습니다.

---

### [실습 1] Hello World 및 환경 확인 (Level 1)

가장 기본적인 워크플로우 구조를 익히고, GitHub이 제공하는 가상 환경의 정보를 확인합니다.

**파일명:** `01-hello-world.yml`

```yaml
name: 01-Hello-World
on: [push] # 저장소에 푸시가 발생하면 무조건 실행

jobs:
  check-environment:
    runs-on: ubuntu-latest
    steps:
      - name: Say Hello
        run: echo "Hello, GitHub Actions!"

      - name: System Info
        run: |
          echo "OS: $(uname -a)"
          echo "User: $(whoami)"
          echo "Workspace: $GITHUB_WORKSPACE"

```

* **사용법**: 파일을 커밋 후 푸시하고 GitHub 상단의 **[Actions]** 탭에서 실행 결과와 로그를 확인합니다.

### [실습 6] Secrets를 이용한 보안 관리 (Level 3)

민감한 정보를 코드에 직접 적지 않고, GitHub의 암호화된 변수 기능을 사용하여 안전하게 전달합니다.

**파일명:** `06-secrets-test.yml`

```yaml
name: 06-Secrets-Handling
on: push

jobs:
  test-secrets:
    runs-on: ubuntu-latest
    steps:
      - name: Use Secret Variable
        env:
          MY_API_KEY: ${{ secrets.MY_AWS_KEY_ID }}
        run: |
          echo "Secret 정보를 불러옵니다..."
          # 실제 로그에서는 *** 로 마스킹되어 보안 처리됩니다.
          echo "The key is $MY_API_KEY" 

```

* **사용법**:
1. GitHub 저장소의 **Settings > Secrets and variables > Actions** 메뉴로 이동합니다.
2. **New repository secret**을 클릭하여 `MY_AWS_KEY_ID`라는 이름으로 값을 저장합니다.
3. 워크플로우 실행 후 로그에서 해당 값이 `***`로 가려지는지 확인합니다.

### [실습 8] AWS S3 정적 웹사이트 배포 (Level 4)

실제 클라우드 환경과 연동하는 실무적인 예제입니다.

**파일명:** `08-aws-s3-deploy.yml`

```yaml
name: 08-S3-Deployment
on:
  push:
    branches: [ "main" ]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Configure AWS Credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: ap-northeast-2

      - name: Sync to S3
        run: |
          aws s3 sync ./public s3://your-unique-bucket-name --delete

```

* **사용법**:
1. AWS IAM에서 S3 접근 권한이 있는 사용자의 Access Key를 생성합니다.
2. GitHub Secrets에 `AWS_ACCESS_KEY_ID`와 `AWS_SECRET_ACCESS_KEY`를 등록합니다.
3. YAML 파일 내의 `s3://your-unique-bucket-name` 부분을 본인의 버킷명으로 수정합니다.

### [중요] AWS 과금 및 유료 서비스 안내

해당 실습들을 진행할 때 발생할 수 있는 주요 과금 항목입니다.

* **AWS S3 (유료)**:
* **데이터 저장**: 월 $0.023/GB (서울 리전 기준).
* **API 호출**: `s3 sync` 시 발생하는 PUT/LIST 요청 1,000건당 **$0.0047** 과금.
* **데이터 전송**: 인터넷으로 나가는 트래픽에 대해 GB당 약 **$0.126** 발생.


* **GitHub Actions (유료 전환 주의)**:
* 프라이빗 저장소에서 **월 2,000분** 무료 제공량을 초과할 경우, 리눅스 러너 기준 **분당 $0.008**이 청구됩니다.
* 빌드 시간이 긴 Docker 이미지 빌드(실습 9번 등) 시 무료 시간을 빠르게 소모할 수 있습니다.


* **AWS ECR (실습 9번 관련)**:
* 저장된 컨테이너 이미지 용량에 따라 **월 $0.10/GB**의 비용이 지속적으로 발생합니다. 실습 종료 후 반드시 레포지토리를 삭제해야 합니다.
