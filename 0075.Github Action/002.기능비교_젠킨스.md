## GitHub Actions vs Jenkins 종합 가이드 및 기능 대칭 분석

**GitHub Actions(GHA)**를 중심으로 전통적 강자인 **Jenkins**와의 차이점을 한눈에 파악할 수 있도록 모든 내용을 통합하여 정리했습니다. 이 자료는 두 도구의 성능, 장단점, 그리고 기능적 대칭성을 깊이 있게 다룹니다.

---

### 1. 종합 비교 및 성능/장단점 분석

두 도구의 근본적인 설계 철학과 운영 방식, 그리고 실무적인 장단점을 비교한 표입니다.

| 구분 | **GitHub Actions (클라우드 네이티브)** | Jenkins (전통적 방식) |
| --- | --- | --- |
| **서비스 형태** | **SaaS** (GitHub 관리형) + Self-hosted 지원 | **Self-hosted** (서버에 직접 설치 및 관리) |
| **설정 방식** | YAML 기반 (Workflow 파일) | Groovy 기반 (Jenkinsfile) |
| **확장성** | GitHub **Marketplace**의 액션 공유 중심 | 1,800개 이상의 **플러그인** 중심 |
| **시작 속도** | 런너 할당 시 대기 시간(Cold Start) 발생 | 서버 상시 가동으로 즉시 실행 |
| **유지보수** | GitHub이 인프라 관리 전담 (관리 공수 낮음) | 서버 관리, 보안 패치, 버전 관리 직접 수행 |
| **통합성** | **GitHub 저장소와 네이티브하게 통합** | 모든 VCS(GitLab, Bitbucket 등) 연동 |
| **성능 제어** | 고정 사양 제공 (고성능 필요 시 전용 런너) | 하드웨어 사양에 따른 완전한 성능 통제 |
| **장점** | 설정 간편, 별도 서버 운영 부담 없음 | 무제한 커스터마이징, 복잡한 로직 구현 |
| **단점** | GitHub 환경 종속, 매우 복잡한 제어에 제약 | **관리 비용 매우 높음**, 플러그인 충돌 위험 |

---

### 2. 기능 대칭 및 단독 기능 상세 비교

두 도구에서 제공하는 기능들을 '트리거'와 '실행 액션', 그리고 각 도구에만 있는 '고유 기능'으로 세분화하여 정리했습니다.

#### ① 트리거(Trigger) 및 이벤트 감지

| 기능 (Trigger) | **GitHub Actions** | Jenkins | 비고 |
| --- | --- | --- | --- |
| **코드 푸시/PR** | **`on: push / pull_request`** | Webhook / Poll SCM | GHA는 네이티브 연동 |
| **시간 예약 (Cron)** | **`on: schedule`** | Build Periodically | - |
| **수동 실행** | **`on: workflow_dispatch`** | Build with Parameters | - |
| **이슈/댓글 감지** | **`on: issues / issue_comment`** | **없음** (플러그인 필요) | GHA의 독보적 강점 |
| **릴리즈/스타 감지** | **`on: release / watch`** | **없음** | GitHub 활동 기반 자동화 |
| **워크플로우 연동** | **`on: workflow_run / call`** | Downstream Project | GHA의 재사용성 우수 |
| **업스트림 감지** | **없음** (GitHub 내 활동만 감지) | **Upstream Project Check** | 타 VCS 연동 시 Jenkins 유리 |
| **API 직접 트리거** | **`on: repository_dispatch`** | Remote Trigger (Token) | - |

#### ② 실행 및 파이프라인 제어

| 기능 (Execution) | **GitHub Actions** | Jenkins | 비고 |
| --- | --- | --- | --- |
| **비밀값 관리** | **`secrets` (저장소/환경 단위)** | Credentials Plugin | - |
| **코드 체크아웃** | **`actions/checkout`** | `checkout scm` | - |
| **병렬 실행** | **`strategy: matrix`** | `parallel { }` | GHA가 설정하기 훨씬 쉬움 |
| **결과물/캐시** | **`upload-artifact / cache`** | Archive / Caching Plugin | GHA는 공식 액션 제공 |
| **실행기 선택** | **`runs-on:`** | `agent { label '...' }` | - |
| **컨테이너 실행** | **`container:`** | `agent { docker { ... } }` | - |
| **수동 승인/대기** | **`environment` (승인 규칙)** | `input` Step | GHA는 특정 플랜 필요 |
| **재사용 라이브러리** | **Reusable Workflows** | **Shared Libraries (Groovy)** | Jenkins는 코드형 관리 강력 |
| **에러 핸들링** | `continue-on-error` | `try-catch-finally` | Jenkins는 프로그래밍 방식 |

### 3. 도구별 단독/특화 기능 (Exclusive Features)

| **GitHub Actions 전용 기능** | **Jenkins 전용 기능** |
| --- | --- |
| **Marketplace**: 2만 개 이상의 액션을 즉시 활용. | **플랫폼 독립성**: GitLab, Bitbucket 등 어디든 연결. |
| **내장된 OIDC**: Access Key 없이 AWS 임시 인증. | **Post-build Actions**: 빌드 후 상세한 후처리 설정. |
| **완전한 환경 격리**: 매번 깨끗한 가상 환경 제공. | **Scripted Pipeline**: Groovy를 통한 무제한 알고리즘. |
| **보안 통합**: CodeQL, Dependabot 등 자동 스캔. | **Fingerprinting**: 아티팩트 간의 관계 추적 및 관리. |

---

### 4. AWS 환경에서의 운영 및 과금 가이드

1. **GitHub Actions 운영 (권장)**
* **보안**: **OIDC(OpenID Connect)**를 활용하여 보안 키 유출 위험을 원천 차단할 수 있습니다.
* **비용**: 비공개 저장소는 무료 시간을 다 쓴 뒤 '분' 단위로 과금되며, **Self-hosted Runner**를 쓰면 GitHub 측 비용은 **0원**입니다.
* **과금 주의**: Windows/macOS 런너 사용 시 가중치(2~10배)가 적용되어 무료 시간이 빨리 소모되니 주의가 필요합니다.


2. **Jenkins 운영**
* **비용**: Master와 Agent 서버를 위해 EC2 인스턴스를 **24시간** 유지해야 하므로 빌드가 없는 시간에도 고정 비용이 발생합니다.
* **관리 부하**: 보안 패치와 플러그인 업데이트를 직접 해야 하며, 서버 장애 시 CI/CD 전체가 마비될 위험이 있습니다.
* **보안**: Credentials에 Access Key를 직접 저장하는 경우가 많아 서버 노출 시 키 유출 위험이 상대적으로 높습니다.
