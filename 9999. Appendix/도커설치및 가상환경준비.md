## 도커(Docker) 설치 및 가상화 환경 준비

Gitea를 안정적으로 구동하기 위해서는 기반 시스템인 도커(Docker) 엔진과 컨테이너 오케스트레이션을 위한 도커 컴포즈(Docker Compose)가 설치되어 있어야 합니다. 이 장에서는 리눅스(Ubuntu) 환경을 기준으로 도커 설치 과정을 단계별로 다룹니다.

---

### 1. 도커 설치 전 사전 준비

기존에 설치된 구버전 도커가 있다면 충돌을 방지하기 위해 먼저 제거합니다.

```bash
sudo apt-get remove docker docker-engine docker.io containerd runc

```

시스템의 패키지 목록을 업데이트하고, 도커 설치에 필요한 필수 패키지들을 설치합니다.

```bash
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg lsb-release

```

---

### 2. 도커 공식 GPG 키 및 저장소 등록

도커 공식 저장소로부터 안전하게 패키지를 내려받기 위해 GPG 키를 등록합니다.

```bash
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

```

---

### 3. 도커 엔진(Docker Engine) 설치

저장소 등록이 완료되면 도커 엔진과 관련 도구들을 설치합니다.

```bash
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-compose-plugin

```

설치가 완료되었는지 확인하기 위해 다음 명령어를 실행합니다.

```bash
# 도커 상태 확인
sudo systemctl status docker

# 헬로월드 컨테이너 실행 테스트
sudo docker run hello-world

```

---

### 4. 사용자 권한 설정 (편의성)

기본적으로 도커 명령어는 `sudo` 권한이 필요합니다. 매번 `sudo`를 입력하는 번거로움을 피하기 위해 현재 사용자를 `docker` 그룹에 추가합니다.

```bash
sudo usermod -aG docker $USER

```

> **주의:** 설정을 적용하려면 로그아웃 후 다시 로그인하거나 `newgrp docker` 명령어를 입력해야 합니다.

---

### 5. 도커 컴포즈(Docker Compose) 확인

최신 도커 설치 방식(Docker Desktop 또는 최신 리눅스 패키지)에서는 `docker-compose-plugin`이 포함되어 있습니다. 이전의 `docker-compose` 명령 대신 `docker compose` (하이픈 제외) 명령어를 사용합니다.

```bash
docker compose version

```

---

### 6. AWS 환경 운영 시 비용 및 주의사항

AWS EC2 인스턴스에 도커를 설치하여 운영할 때 고려해야 할 경제적 요소입니다.

| 항목 | 상세 내용 | 과금 주의 |
| --- | --- | --- |
| **인스턴스 타입** | 도커 엔진 자체는 가볍지만, 여러 컨테이너 구동 시 CPU/RAM 점유율 상승 | 프리티어(t2.micro/t3.micro) 범위를 벗어나는 워크로드 시 인스턴스 비용 증가 |
| **데이터 전송** | 도커 허브(Docker Hub)에서 이미지 풀(Pull) 시 데이터 발생 | 외부 인터넷망을 통한 데이터 전송 요금(Data Transfer Out) 확인 |
| **EBS 용량** | 도커 이미지와 컨테이너 로그, 볼륨 데이터가 저장됨 | `/var/lib/docker` 경로의 용량이 늘어나면 EBS 추가 비용 발생 |
