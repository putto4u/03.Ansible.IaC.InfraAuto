## 도커 컨테이너 삭제와 데이터 영구 보존의 원리

도커를 사용하여 Gitea를 설치할 때 가장 많이 하시는 질문 중 하나입니다. 결론부터 말씀드리면, **데이터를 어떻게 설정했느냐(Volume 설정 여부)**에 따라 모든 것이 지워질 수도, 데이터만 살아남을 수도 있습니다.

---

### 1. 기본 원칙: 컨테이너의 휘발성 (Ephemerality)

도커 컨테이너는 기본적으로 **'쓰고 버리는'** 설계 철학을 가지고 있습니다.

* **볼륨 설정을 하지 않은 경우:** 컨테이너 내부에 저장된 모든 데이터(Git 저장소, DB, 설정 파일 등)는 컨테이너 삭제(`docker rm`) 시 함께 파괴됩니다. 이를 **휘발성(Volatile)** 상태라고 합니다.
* **볼륨 설정을 한 경우:** 컨테이너가 삭제되더라도 실제 데이터는 호스트 PC(서버)의 특정 디렉토리에 물리적으로 남아 있습니다. 나중에 새 컨테이너를 만들어 이 디렉토리에 다시 연결하면 데이터가 그대로 복구됩니다.

---

### 2. 데이터 보존의 핵심: 도커 볼륨 (Docker Volumes)

앞서 우리가 작성했던 `docker-compose.yml` 파일의 `volumes` 항목이 바로 이 역할을 수행합니다.

```yaml
volumes:
  - ./data:/data  # 호스트의 ./data 폴더를 컨테이너의 /data에 연결

```

* **좌측 (`./data`):** 내 서버(호스트)의 실제 하드디스크 경로입니다.
* **우측 (`/data`):** 컨테이너 내부에서 바라보는 가상의 경로입니다.

이 설정을 해두었다면, `docker compose down`으로 컨테이너를 삭제하더라도 내 서버의 `./data` 폴더 안에는 사용자가 올린 소스 코드와 데이터베이스 파일이 **고스란히 유지**됩니다.

---

### 3. 완전 삭제를 원할 때 (깔끔하게 지우기)

만약 연습용으로 구축했다가 흔적도 없이 지우고 싶다면 다음 단계를 따라야 합니다.

1. **컨테이너 및 네트워크 삭제:**
```bash
docker compose down

```


2. **물리 데이터 삭제:**
`docker-compose.yml` 파일이 있는 위치에서 볼륨으로 지정했던 폴더를 직접 삭제합니다.
```bash
sudo rm -rf ./data

```


3. **이미지 삭제 (선택 사항):**
다운로드했던 Gitea 이미지를 지워 용량을 확보합니다.
```bash
docker rmi gitea/gitea:latest

```



---

### 4. AWS 환경에서의 데이터 유지 비용

AWS EC2에서 도커 볼륨을 사용할 때 경제적으로 주의해야 할 점입니다.

| 상황 | 데이터 상태 | 과금 발생 여부 |
| --- | --- | --- |
| **컨테이너만 삭제** | 데이터(EBS)에 남음 | **과금 계속 발생** (EBS 용량 점유) |
| **EC2 인스턴스 중지** | 데이터(EBS)에 남음 | **과금 계속 발생** (EBS 보관 비용) |
| **인스턴스 및 EBS 삭제** | 데이터 완전 소멸 | **과금 중단** |

> **중요:** 컨테이너를 지운다고 해서 AWS의 EBS(하드디스크) 용량이 줄어드는 것은 아닙니다. 데이터가 담긴 폴더를 비우거나 인스턴스를 종료해야 비용 발생을 완전히 막을 수 있습니다.

---

### 5. 데이터 보존 여부 확인 방법

현재 내 컨테이너가 데이터를 안전하게 밖으로 빼내고 있는지 확인하려면 다음 명령어를 사용하세요.

```bash
docker inspect [컨테이너명] | grep -A 20 Mounts

```

이 결과에서 `Source`가 내 실제 서버 경로를 가리키고 있다면, 컨테이너를 지워도 데이터는 안전합니다.
