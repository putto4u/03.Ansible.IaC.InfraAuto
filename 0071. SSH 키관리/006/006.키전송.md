## SSH 키(Key) 전송 및 복사

SSH 접속 시 비밀번호 대신 공개키 기반 인증을 사용하면 보안을 강화하고 자동화된 로그인을 구현할 수 있습니다. 로컬 PC에서 생성한 공개키를 원격 서버로 전송하는 과정은 다음과 같습니다.

### 1. 로컬 환경에서 키 쌍(Key Pair) 생성

먼저 전송할 키가 없다면 로컬 터미널에서 키 쌍을 생성해야 합니다.

```bash
ssh-keygen -t rsa -b 4096

```

* `Enter file in which to save the key`: 엔터를 눌러 기본 경로(`~/.ssh/id_rsa`)에 저장합니다.
* `Enter passphrase`: 추가 보안을 위해 암호를 입력하거나, 자동화를 원할 경우 엔터를 눌러 생략합니다.

### 2. 원격 서버로 공개키 전송 (ssh-copy-id)

가장 빠르고 권장되는 방법입니다. 이 명령어는 서버의 `~/.ssh/authorized_keys` 파일에 로컬의 공개키를 자동으로 추가해 줍니다.

```bash
ssh-copy-id -i ~/.ssh/id_rsa.pub [사용자명]@[원격_서버_IP]

```

* 최초 실행 시 서버의 비밀번호를 요구합니다.
* 전송이 완료되면 이후부터는 비밀번호 없이 `ssh [사용자명]@[원격_서버_IP]` 명령어로 바로 접속이 가능합니다.

### 3. 수동으로 키 전송하기

`ssh-copy-id`를 사용할 수 없는 환경(예: 특정 포트 사용 등)에서는 수동으로 전송할 수 있습니다.

```bash
cat ~/.ssh/id_rsa.pub | ssh [사용자명]@[원격_서버_IP] "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

```

### 4. 권한 설정 확인

키 전송 후 접속이 되지 않는다면 서버 측의 디렉토리 및 파일 권한이 보안 정책에 맞게 설정되었는지 확인해야 합니다.

* **.ssh 디렉토리**: `700` (drwx------)
* **authorized_keys 파일**: `600` (-rw-------)

---

### 키 전송 방법 비교

| 방법 | 명령어 | 특징 |
| --- | --- | --- |
| **ssh-copy-id** | `ssh-copy-id -i [키경로] [대상]` | 가장 표준적이고 안전한 자동 전송 방식 |
| **SCP 이용** | `scp [키경로] [대상]:~/.ssh/` | 파일을 직접 복사한 뒤 수동으로 등록 필요 |
| **수동 복사** | `cat >> authorized_keys` | 명령어 조합을 통해 직접 텍스트 추가 |
