### GitOps 기반의 인프라 엔진 및 설정 통합 자동 배포

Nginx 설치 단계(Task 1)마저 GitHub에 정의된 스크립트로 관리하면, 향후 Apache, Lighttpd 등 다른 웹 엔진으로 교체할 때 내 PC의 코드를 수정할 필요 없이 GitHub의 설정 파일만 변경하여 모든 서버에 일괄 적용할 수 있습니다.

---

## 1. 프로젝트 구조 (완전한 중앙 집중형)

모든 설치 로직과 엔진 설정이 GitHub 저장소(`web_dep`)에 집중됩니다.

```text
~/projects/web_dep/
├── .gitignore
├── web_dep.yml          # [내 PC] 배포 실행 트리거
├── deploy_logic.yml     # [GitHub] 전체 서버 구성 로직 (설치 + 설정 + 배포)
├── setup/               # [GitHub] 엔진 설치 관련 스크립트 및 변수
│   └── install_engine.sh # 웹 엔진 설치 스크립트 (Nginx, Apache 등 교체 가능)
├── nginx/               # [GitHub] 엔진 상세 설정 폴더
│   └── default.conf
└── webdev/              # [GitHub] 실제 서비스 소스 폴더
    └── index.html

```

---

## 2. [GitHub] 웹 엔진 교체가 용이한 배포 로직 작성

기존의 `apt` 모듈 대신 GitHub에 포함된 설치 스크립트를 실행하도록 하여 유연성을 높였습니다.

**`deploy_logic.yml` (GitHub 업로드용)**

```yaml
---
- name: 웹 엔진 및 서비스 통합 배포 파이프라인
  hosts: webservers
  become: true
  tasks:
    - name: 1. GitHub 저장소 최종본 임시 클론
      git:
        repo: "https://github.com/사용자계정/web_dep.git"
        dest: "/tmp/web_dep_final"
        version: main
        force: yes

    - name: 2. 웹 엔진 설치 (GitHub 내 스크립트 실행)
      # 스크립트 내용만 바꾸면 Nginx에서 다른 엔진으로 즉시 교체 가능
      shell: "bash /tmp/web_dep_final/setup/install_engine.sh"

    - name: 3. 커스텀 엔진 설정 파일 적용
      copy:
        src: "/tmp/web_dep_final/nginx/default.conf"
        dest: "/etc/nginx/sites-available/default"
        remote_src: yes
        owner: root
        group: root
        mode: '0644'
      notify: Reload Engine

    - name: 4. webdev 콘텐츠 배포
      copy:
        src: "/tmp/web_dep_final/webdev/"
        dest: "/var/www/html/"
        remote_src: yes
        owner: www-data
        group: www-data
        mode: '0644'

    - name: 5. 임시 디렉토리 정리
      file:
        path: "/tmp/web_dep_final"
        state: absent

  handlers:
    - name: Reload Engine
      service:
        name: nginx
        state: reloaded

```

## 3. [GitHub] 엔진 설치 스크립트 작성

**`setup/install_engine.sh` (Nginx 예시)**

```bash
#!/bin/bash
# 다른 엔진으로 교체 시 이 파일의 내용만 수정하여 커밋하면 됩니다.
apt-get update
apt-get install -y nginx

```

---

## 4. 실습 운영 사이클

이제 모든 인프라의 운명은 GitHub 커밋에 달려 있습니다.

1. **엔진 변경**: Apache로 바꾸고 싶다면 GitHub의 `install_engine.sh`와 `default.conf`를 수정하여 푸시합니다.
2. **최종 커밋 및 푸시**:
```bash
git add .
git commit -m "Feature: 엔진 설치 로직 및 설정의 중앙 관리화"
git push origin main

```


3. **배포 지시**: 내 PC에서 단 한 줄의 명령으로 10대 서버의 운명을 결정합니다.
```bash
ansible-playbook -i inventory.ini web_dep.yml

```

## 5. AWS 관련 비용 및 보안 주의사항

* **AWS EC2 인스턴스 종료**: 10대의 인스턴스(`101~110`) 실습 시, **Free Tier** 무료 제공 시간은 약 **3일(75시간)**이면 바닥납니다. 실습을 중단하거나 완료한 직후에는 반드시 AWS 콘솔에서 모든 인스턴스를 **종료(Terminate)** 하십시오.
* **쉘 스크립트 실행 권한**: `shell` 모듈로 스크립트를 실행할 때 권한 문제가 발생할 수 있습니다. 스크립트 작성 시 실행 권한을 확인하거나 플레이북에서 `chmod`를 선행하십시오.
* **유료 서비스 전환 주의**: 본 예제에서 사용하는 EC2 인스턴스 외에 Elastic Load Balancer(ELB) 등을 추가로 구성할 경우 즉시 비용이 발생할 수 있습니다.
