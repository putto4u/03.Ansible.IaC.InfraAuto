### Git과 Ansible을 활용한 웹 애플리케이션 자동화 배포 실습

이 과정은 관리자 PC(Control Node), 원격 저장소(GitHub), 그리고 대상 서버(Managed Node) 간의 상호작용을 이해하는 것이 핵심입니다. 각 단계가 어느 위치에서 수행되는지 명확히 구분하여 실습을 진행합니다.

---

## 1. 작업 환경 및 흐름도

본 실습은 세 가지 환경을 연결하여 진행됩니다.

* **내 PC (Local Control Node):** 코드를 작성하고, Git으로 관리하며, Ansible 명령을 내려 서버를 제어하는 곳입니다.
* **GitHub (Remote Repository):** 작성한 코드와 설정 파일이 저장되는 중앙 저장소입니다.
* **원격 서버 (Managed Node/AWS EC2):** 실제 웹 서비스가 구동되고 Ansible에 의해 설정되는 대상입니다.

---

## 2. 단계별 수행 위치 및 실습 절차

### 단계 1: 프로젝트 초기화 및 소스 작성 (**위치: 내 PC**)

로컬 환경에서 프로젝트의 기초를 다집니다.

```bash
# 프로젝트 디렉토리 생성
mkdir web-deploy-project
cd web-deploy-project

# Git 저장소 초기화
git init

# 배포할 웹 소스 파일 생성
echo "<h1>Ansible & Git Auto Deployment</h1>" > index.html

```

### 단계 2: 원격 저장소 생성 및 연결 (**위치: GitHub & 내 PC**)

1. **GitHub 웹사이트**: 새로운 Repository(예: `web-deploy-project`)를 생성합니다.
2. **내 PC**: 생성한 GitHub 주소를 로컬 저장소에 연결하고 코드를 올립니다.

```bash
# 내 PC에서 수행
git remote add origin https://github.com/사용자계정/web-deploy-project.git
git add .
git commit -m "Initial commit"
git push -u origin main

```

### 단계 3: Ansible 설정 파일(YAML) 작성 (**위치: 내 PC**)

서버에 무엇을 할 것인지 정의하는 파일을 작성합니다. 이 파일들도 Git으로 관리됩니다.

* **inventory.ini**: 대상 서버 IP 및 접속 정보 기재
* **deploy.yml**: Nginx 설치 및 Git 코드 클론 절차 정의

```yaml
# deploy.yml 내용 중 일부 (내 PC에서 작성)
    - name: Git 저장소에서 최신 코드 배포
      git:
        repo: "https://github.com/사용자계정/web-deploy-project.git"
        dest: "/var/www/html"
        version: main

```

### 단계 4: 자동화 배포 실행 (**위치: 내 PC → 원격 서버**)

내 PC에서 Ansible 명령을 실행하면, **원격 서버**가 **GitHub**에 접속하여 최신 코드를 가져오도록 명령합니다.

```bash
# 내 PC에서 실행
ansible-playbook -i inventory.ini deploy.yml

```

### 단계 5: 코드 수정 및 업데이트 (**위치: 내 PC → GitHub → 내 PC**)

1. **내 PC**: `index.html` 내용을 수정하고 `git push`로 GitHub에 올립니다.
2. **내 PC**: 다시 `ansible-playbook`을 실행합니다.
3. **원격 서버**: Ansible의 명령을 받아 GitHub에서 수정된 최신 코드를 가져와 웹 페이지를 갱신합니다.

---

## 3. 환경별 역할 요약표

| 실행 위치 | 수행 작업 | 결과물 |
| --- | --- | --- |
| **내 PC** | 코드 작성, YAML 설정, Git 커밋/푸시, Ansible 실행 | 프로젝트 코드 및 설정 제어 |
| **GitHub** | 소스 코드 및 플레이북 보관 | 중앙 집중식 코드 저장소 |
| **원격 서버** | Nginx 설치, GitHub에서 코드 다운로드(Clone/Pull) | 실제 웹 서비스 제공 |

---

## 4. AWS 관련 비용 및 주의사항

* **Amazon EC2 (Managed Node)**: 실습용 서버로 EC2를 생성할 때 **Free Tier(t2.micro 등)**인지 반드시 확인하세요. 24시간 가동 시 무료 할당량이 소진될 수 있습니다.
* **네트워크 트래픽**: 원격 서버가 GitHub에서 코드를 가져올 때 외부 인터넷 통신이 발생합니다. 일반적인 텍스트 파일 배포는 거의 비용이 발생하지 않으나, 대용량 파일 배포 시 유의해야 합니다.
* **보안 그룹 (Security Group)**: 원격 서버의 **80(HTTP)** 포트와 **22(SSH)** 포트가 열려 있어야 내 PC에서 접속하고 웹 페이지를 확인할 수 있습니다.
