# YAML (YAML Ain't Markup Language) 가이드

YAML은 'YAML Ain't Markup Language'의 약자로, 데이터 직렬화에 특화된 인간 친화적인 언어입니다. 주로 설정 파일(Configuration), 데이터 교환, 인프라 관리(IaC) 등에서 널리 사용됩니다.

---

## YAML의 핵심 철학 및 구조

YAML은 데이터의 계층 구조를 나타내기 위해 가독성을 최우선으로 설계되었습니다. XML의 복잡한 태그나 JSON의 중괄호(`{}`) 대신, **줄바꿈**과 **들여쓰기(Indentation)**를 사용하여 데이터의 상하 관계를 정의합니다.

### 1. 기본 문법 규칙

* **들여쓰기**: 탭(Tab) 대신 **공백(Space)**을 사용합니다. 일반적으로 2칸 또는 4칸을 사용하며, 동일한 계층은 반드시 같은 수의 공백을 가져야 합니다.
* **대소문자 구분**: 키(Key)와 값(Value) 모두 대소문자를 엄격하게 구분합니다.
* **주석**: `#` 기호를 사용하여 작성하며, 해당 줄의 끝까지 주석 처리됩니다.

### 2. 기본 데이터 타입 (Scalar)

YAML은 문자열, 숫자, 불리언 등 기본적인 타입을 자동으로 인식합니다.

```yaml
integer: 12345              # 정수
float: 3.14                 # 실수
string: "Hello YAML"        # 문자열 (따옴표 생략 가능)
boolean: true               # 불리언 (true, false)
null_value: null            # 빈 값

```

## 데이터 구조의 시각화

YAML의 데이터 구조는 크게 세 가지 방식으로 나뉩니다: **Mapping(Hash/Dict)**, **Sequence(List/Array)**, 그리고 **Scalars**.

### 1. Mapping (Key-Value)

가장 기본이 되는 구조로, `키: 값` 형태로 작성합니다. `:` 뒤에는 반드시 공백이 하나 있어야 합니다.

```yaml
# User 정보 매핑
name: John Doe
age: 30
job: Developer

```

### 2. Sequence (List)

목열을 나타낼 때는 하이픈(`-`)을 사용합니다. 각 항목은 동일한 들여쓰기 수준을 유지해야 합니다.

```yaml
# 과일 목록 리스트
fruits:
  - Apple
  - Banana
  - Orange

```

### 3. 중첩 구조 (Nested Structure)

매핑 안에 리스트를 넣거나, 리스트 안에 매핑을 넣어 복잡한 데이터를 표현할 수 있습니다.

```yaml
# 사용자별 보유 기술 목록
users:
  - name: Alice
    skills:
      - Python
      - Docker
  - name: Bob
    skills:
      - AWS
      - Terraform

```

## 고급 문법 및 편의 기능

### 1. 다중 줄 문자열 처리

긴 문장을 입력할 때 줄바꿈 유지 여부에 따라 두 가지 기호를 사용합니다.

* `|` (Literal Block Scalar): 줄바꿈을 그대로 유지합니다.
* `>` (Folded Block Scalar): 줄바꿈을 공백으로 치환하여 한 줄로 취급합니다.

```yaml
# 줄바꿈 유지
literal_sample: |
  첫 번째 줄
  두 번째 줄

# 한 줄로 합치기
folded_sample: >
  이 문장은 여러 줄로
  작성되었지만 실제로는
  한 줄로 읽힙니다.

```

### 2. 문서 구분자 (`---`, `...`)

한 파일 내에서 여러 개의 YAML 문서를 구분할 때 `---`를 사용합니다. 문서의 끝을 명시적으로 알릴 때는 `...`을 사용합니다.

```yaml
---
# 첫 번째 문서: 설정값
version: 1.0
---
# 두 번째 문서: 서비스 정보
service: web-app
...

```

### 3. 데이터 재사용 (Anchor & Alias)

특정 설정을 반복해서 사용해야 할 때 **Anchor(`&`)**로 정의하고 **Alias(`*`)**로 참조할 수 있습니다.

```yaml
# 공통 설정 정의
common_config: &default_setting
  timeout: 30
  retry: 3

# 설정 참조 및 확장
production:
  <<: *default_setting
  env: prod

development:
  <<: *default_setting
  env: dev

```

## AWS 환경에서의 YAML 활용 (CloudFormation)

AWS 인프라를 코드로 관리할 때 YAML은 매우 중요하게 사용됩니다. 대표적으로 **AWS CloudFormation** 템플릿이 YAML 형식을 지원합니다.

> [!CAUTION]
> **과금 주의**: CloudFormation 자체 사용은 무료인 경우가 많으나, YAML 템플릿을 통해 생성되는 리소스(EC2, RDS, NAT Gateway 등)는 **실제 비용이 즉시 발생**합니다. 테스트 후에는 반드시 `Stack Delete`를 통해 리소스를 제거해야 유료 전환 및 과금을 방지할 수 있습니다.

```yaml
# EC2 인스턴스 생성 예시 (유료 서비스 포함)
Resources:
  MyEC2Instance:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: t3.micro  # 프리티어 여부 확인 필요 (과금 발생 가능)
      ImageId: ami-0abcdef1234567890

```

## YAML vs JSON 비교

YAML과 JSON은 데이터를 표현한다는 점에서 유사하지만 목적에 따라 차이가 있습니다.

| 특징 | YAML | JSON |
| --- | --- | --- |
| **가독성** | 매우 높음 (인간 중심) | 보통 (기계 중심) |
| **주석** | 지원함 (`#`) | 지원하지 않음 |
| **구문** | 들여쓰기 중심 | 중괄호, 대괄호 중심 |
| **주요 용도** | 설정 파일, CI/CD 파이프라인 | API 응답, 웹 데이터 전송 |
