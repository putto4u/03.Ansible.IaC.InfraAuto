앤서블을 활용하여 대규모 인프라를 효율적이고 안전하게 관리하기 위한 심화 전략들을 정리합니다. `serial`을 이용한 안정적인 배포부터 대규모 환경에서의 병목 현상 해결까지, 실무에서 필수적으로 다루는 기술들입니다.

---

## 1. `serial` 옵션을 활용한 롤링 업데이트(Rolling Update)

수백 대의 서버를 동시에 업데이트하다가 오류가 발생하면 전체 서비스가 중단될 위험이 있습니다. `serial` 옵션은 작업을 수행할 호스트의 단위를 나누어 순차적으로 실행하게 합니다.

```yaml
- name: 웹 서버 롤링 업데이트
  hosts: webservers
  serial: "20%"  # 전체 서버의 20%씩 나누어 실행 (또는 숫자 '5'와 같이 지정 가능)
  max_fail_percentage: 10 # 실패율이 10%를 넘으면 전체 플레이북 중단
  
  tasks:
    - name: Nginx 서비스 재시작
      ansible.builtin.systemd:
        name: nginx
        state: restarted

```

* **동작 방식:** 첫 번째 20%의 서버 그룹이 모든 태스크를 성공적으로 마쳐야만 다음 20%로 넘어갑니다.
* **장점:** 서비스 가용성을 유지(Zero Downtime)하면서 배포 리스크를 최소화합니다.

---

## 2. 대규모 호스트 관리 시 API Throttling 및 로깅 전략

AWS와 같은 클라우드 환경에서 동시에 너무 많은 요청을 보내면 AWS API가 접속을 제한(Throttling)합니다.

* **Throttling 회피:** * `forks` 수치를 무조건 높이기보다 적정 수준(50~100)으로 유지합니다.
* AWS 동적 인벤토리(Dynamic Inventory) 사용 시 `cache: yes` 설정을 통해 API 호출 횟수를 줄입니다.


* **로깅 전략:** * `ansible.cfg`에서 `log_path`를 지정하여 모든 실행 이력을 파일로 남깁니다.
* **과금 주의:** 로그 파일이 커지면 EBS 용량을 차지하므로 `logrotate`를 함께 설정해야 추가적인 스토리지 비용을 방지할 수 있습니다.



---

## 3. SSH ControlMaster 상세 옵션 및 트러블슈팅

SSH 연결을 매번 새로 맺는 비용을 줄이기 위해 기존 연결을 재사용하는 설정입니다.

```ini
[ssh_connection]
ssh_args = -o ControlMaster=auto -o ControlPersist=60s

```

* **ControlMaster=auto:** 첫 번째 연결을 마스터 세션으로 만들고 이후 연결은 이를 공유합니다.
* **ControlPersist=60s:** 마지막 연결이 끝난 후에도 60초간 통로를 열어두어 다음 작업의 응답 속도를 높입니다.
* **트러블슈팅:** "Control socket exists" 에러 발생 시 `/tmp/` 아래의 소켓 파일을 삭제하거나 제어 노드를 재시작하면 해결됩니다.

---

## 4. Redis를 활용한 고성능 팩트 캐싱(Fact Caching)

수천 대의 서버 정보를 로컬 파일로 캐싱하면 디스크 I/O 병목이 발생할 수 있습니다. 이때 인메모리 데이터베이스인 Redis를 사용합니다.

* **설정 방법:**
```ini
[defaults]
fact_caching = redis
fact_caching_connection = localhost:6379:0

```


* **AWS 관련 비용:** AWS **ElastiCache(Redis)**를 사용할 경우 노드 타입에 따라 **시간당 과금**이 발생하므로, 소규모라면 제어 노드 안에 Redis를 직접 설치해 사용하는 것이 비용 효율적입니다.

---

## 5. 실행 속도 가시성 확보 (Callback Plugins)

어떤 태스크에서 시간이 오래 걸리는지 파악하는 것은 최적화의 첫걸음입니다.

* **설정 방법:** `ansible.cfg`에 다음을 추가합니다.
```ini
[defaults]
callbacks_enabled = profile_tasks, timer

```


* **효과:** 각 태스크별 실행 시간이 초 단위로 출력되어, 병목 구간을 즉시 파악할 수 있습니다.
