Ansible 플레이북 제작의 핵심인 **YAML 파일 작성법**과 **변수(Variable) 작성법**에 대해 좀 더 자세히 설명해 드리겠습니다. 이는 IaC(Infrastructure as Code)를 전문적으로 다루는 데 필수적인 기초 지식입니다.

-----

## 1\. YAML 파일 제작 핵심 (플레이북 구조) 📝

YAML(YAML Ain't Markup Language)은 사람이 읽기 쉬운 데이터 직렬화 표준으로, Ansible 플레이북을 작성하는 데 사용됩니다.

### 1.1. 기본 문법 규칙

| 규칙 | 설명 | 예제 |
| :--- | :--- | :--- |
| **들여쓰기 (Indentation)** | 오직 \*\*스페이스(Space)\*\*만을 사용하며, 일반적으로 **2칸**을 사용합니다. 탭(Tab)은 절대 사용해서는 안 됩니다. | `tasks:`<br>`&nbsp;&nbsp;- name: ...` |
| **리스트 (List)** | 항목 앞에 **하이픈(-)과 공백을 붙여서 표현합니다. Ansible의 `tasks`나 `handlers`가 이 구조입니다. | `- name: install_pkg`<br>`- name: copy_file` |
| 키-값 쌍 (Dictionary) | 콜론(:**) 다음에 **공백**을 두고 값을 작성합니다. YAML의 가장 기본적인 데이터 구조입니다. | `hosts: webservers`<br>`name: nginx` |
| **시작 표시** | 파일의 시작을 알리는 \*\*`---`\*\*로 시작하는 것이 관례입니다. | `---`<br>`- name: ...` |

### 1.2. 플레이북의 기본 구조 다시 보기

Ansible 플레이북은 **리스트**로 시작하며, 각 리스트 항목은 하나 이상의 \*\*플레이(Play)\*\*를 정의합니다.

#### deploy_python3.yml
```

# 리스트의 첫 번째 항목 = 첫 번째 플레이
- name: 웹 서버 초기 설정 플레이
  hosts: webservers          # 대상 호스트 (키-값 쌍)
  become: yes
  
  tasks:                     # 리스트 (작업 목록)
    - name: Ensure Python installed # 리스트 항목 = 태스크 이름
      ansible.builtin.apt:    # <--- "이 모듈(도구)을 쓰겠다"는 선언 (Key)
        name: python3         # <--- 모듈에 전달할 옵션 1 (Value 내의 상세 설정)
        state: present        # <--- 모듈에 전달할 옵션 2
```
```
# Ansible 실행 명령어
ansible-playbook -i inventory.ini deploy_web.yml
```
### 한줄 명령어

``` ansible webservers -m ansible.builtin.apt -a "name=python3 state=present" --become ```

## 2\. 플레이북 변수(Variable) 작성법 💡

변수는 플레이북의 유연성과 재사용성을 극대화하는 IaC의 핵심 요소입니다.

### **병렬 실행 (Fork)**:
* 기본적으로 앤서블은 5개의 호스트를 동시에 관리합니다. 인스턴스가 수백 대라면 `-f` 옵션으로 개수를 늘릴 수 있지만, 이 경우 제어 노드의 CPU 사용량이 급증할 수 있습니다.

### 2.1. 변수 정의 및 사용법

Ansible에서 변수를 사용하는 형식은 \*\*`{{ variable_name }}`\*\*입니다.

| 변수 정의 위치 | 사용 목적 | 예제 코드 |
| :--- | :--- | :--- |
| **`vars` 섹션** | 해당 플레이북 내부에서만 사용할 로컬 변수. | `vars:`<br>`&nbsp;&nbsp;nginx_port: 80` |
| **인벤토리 파일** | 특정 호스트 그룹 또는 개별 호스트에 고정적으로 적용할 값. | `[webservers]`<br>`web1 http_port=80` |
| **외부 파일 (`vars_files`)** | 변수가 많을 때 별도의 YAML 파일로 분리하여 관리. | `vars_files:`<br>`&nbsp;&nbsp;- "vars/common.yml"` |

### 2.2. 플레이북 내 `vars` 섹션 예제

가장 흔하게 사용되는 **`vars`** 섹션 정의 예제입니다.


#### deploy_mariadb_userdb.yml

```yaml

- name: Install and Configure MariaDB
  hosts: database_servers
  become: yes
  
  vars:
    # 데이터베이스 버전 변수 정의
    db_version: 10.6
    # 관리자 계정 변수 정의 (민감 정보는 Vault 사용 권장)
    admin_user: dbadmin

  tasks:
    - name: Install MariaDB version {{ db_version }}
      ansible.builtin.apt:
        name: mariadb-server-{{ db_version }}
        state: present
    
    - name: Create database user {{ admin_user }}
      community.mysql.mysql_user:
        name: "{{ admin_user }}"
        host: "%"
        password: "MySecurePassword"
        priv: "*.*:ALL"
        state: present
```

### 2.3. ⚠️ 실전 팁: 민감 정보 관리 (Ansible Vault)

비밀번호, API 키와 같은 민감한 정보(Secret Data)는 절대 일반 텍스트 플레이북에 노출해서는 안 됩니다.

  * **Ansible Vault**: Ansible에 내장된 암호화 도구를 사용하여 민감한 변수 파일이나 문자열을 암호화해야 합니다.
      * 암호화된 파일은 일반 텍스트처럼 플레이북에서 사용되지만, 실행 시에만 Vault 비밀번호를 입력하여 복호화됩니다. 이는 **보안적인 IaC** 구축의 필수 단계입니다.

YAML 문법과 변수 사용법을 숙달하면, 복잡한 인프라 구성도 간결하고 재사용 가능한 코드로 쉽게 자동화할 수 있습니다.

앤서블 플레이북 파일(`.yml`)을 실행할 때는 `ansible-playbook` 명령어를 사용하지만, 질문하신 것처럼 특정 **모듈 하나만** 커맨드 라인에서 즉시 실행하고 싶을 때는 **애드혹(Ad-hoc) 명령어**를 사용합니다.

## 1. 애드혹(Ad-hoc) 명령어 구조

플레이북을 만들지 않고 터미널에서 바로 모듈을 실행하는 방법입니다. 복잡한 설정 없이 한 줄로 작업을 끝낼 때 유용합니다.

```bash
ansible [대상_호스트] -m [모듈_이름] -a "[모듈_옵션]" --become

```

### 파이썬 설치 예시 (작성하신 코드를 커맨드로 변환)

```bash
ansible webservers -m ansible.builtin.apt -a "name=python3 state=present" --become

```

* **`webservers`**: 인벤토리에 정의된 대상 그룹입니다.
* **`-m ansible.builtin.apt`**: 사용할 모듈을 지정합니다. (`-m`은 module의 약자)
* **`-a "name=python3 state=present"`**: 모듈에 전달할 인자(Arguments)입니다. 키=값 형태로 한 줄에 적습니다. (`-a`는 args의 약자)
* **`--become`**: 관리자(root) 권한으로 실행하라는 옵션입니다. (플레이북의 `become: yes`와 동일)

## 3. 실행 시 주의사항 및 AWS 과금 관련

1. **멱등성 확인**: 커맨드 실행 후 결과 창의 색상을 확인하세요.
* **<span style="color:yellow">SUCCESS (Changed)</span>**: 실제로 설치나 변경이 일어남.
* **<span style="color:green">SUCCESS (OK)</span>**: 이미 설치되어 있어 아무 작업도 하지 않음. (멱등성 확인 가능)


2. **AWS 보안 그룹 및 비용**:
* **SSH 트래픽**: 커맨드를 실행할 때마다 SSH 접속이 발생합니다. 빈번한 대량의 애드혹 명령어 실행은 네트워크 트래픽을 발생시키며, AWS 외부에서 접속할 경우 **Data Transfer Out** 비용이 계산될 수 있습니다.
* **유료 패키지 주의**: 일부 서드파티 리포지토리나 상용 소프트웨어를 `apt` 모듈로 설치할 경우 별도의 라이선스 비용이 발생할 수 있으니 패키지 출처를 확인하세요.
