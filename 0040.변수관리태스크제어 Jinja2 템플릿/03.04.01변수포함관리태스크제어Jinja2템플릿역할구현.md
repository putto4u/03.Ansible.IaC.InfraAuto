Ansible에서 **변수(Variable) 관리**, **포함(Include) 및 가져오기(Import) 태스크 제어**, 그리고 **Jinja2 템플릿 역할 구현**은 복잡한 IaC(Infrastructure as Code) 프로젝트를 체계적이고 유연하게 관리하기 위한 핵심 기술입니다.

-----

## 1\. 변수 관리 및 제어 방법 ⚙️

Ansible은 변수를 정의하고 사용하는 다양한 방법을 제공하여, 환경별 또는 호스트별 설정을 쉽게 분리하고 관리할 수 있게 합니다.

### 1.1. 변수의 우선순위 이해

Ansible은 변수가 여러 위치에서 정의될 경우, 어떤 변수를 최종적으로 적용할지 결정하는 **명확한 우선순위**를 가지고 있습니다. 실무에서는 이 우선순위를 이해하는 것이 중요합니다. (숫자가 높을수록 우선순위가 높음)

| 우선순위 | 변수 정의 위치 | 설명 |
| :--- | :--- | :--- |
| **최하** | **Role Defaults** | Role의 기본값. 다른 곳에서 정의되지 않았을 때만 사용됩니다. |
| **중간** | **Inventory Variables** | `host_vars` (호스트별), `group_vars` (그룹별) 파일에서 정의됩니다. 환경 분리에 주로 사용됩니다. |
| **중상** | **Play Variables** | 플레이북 내 `vars:` 섹션에 정의됩니다. |
| **최상** | **Extra Variables (`-e`)** | 명령줄에서 `-e "변수=값"` 형태로 전달되며, **모든 설정을 덮어씁니다.** 긴급 패치나 일회성 변경에 사용됩니다. |

### 1.2. 변수 파일 분리 및 사용

실무에서는 \*\*`group_vars`\*\*와 **`host_vars`** 디렉토리를 사용해 변수를 중앙 집중식으로 관리하는 것이 표준입니다.

```
/ansible_project/
├── inventory.ini
├── group_vars/
│   ├── webservers.yml    # webservers 그룹에 공통 적용될 변수
│   └── dbservers.yml     # dbservers 그룹에 공통 적용될 변수
└── host_vars/
    └── web1.yml          # web1 호스트에만 적용될 개별 변수
```

**`group_vars/webservers.yml` 예시:**

```yaml
---
# Nginx 설정 공통 변수
web_service_name: nginx
http_port: 80

# 환경 변수 (dev, prod 등으로 분리하여 활용)
environment: dev
```

## 2\. 태스크 제어: Include vs. Import (동적 vs. 정적) 🔗

Ansible에서 여러 태스크 파일을 분리하여 모듈화할 때, \*\*`include`\*\*와 \*\*`import`\*\*는 작동 방식에 큰 차이가 있습니다.

### 2.1. `import_tasks` (정적 통합)

  * **특징**: 플레이북 실행 전에 파일 내용을 읽어와 **정적으로** 통합합니다.
  * **용도**: 플레이북 실행 전에 모든 구조가 확정되어야 할 때 사용합니다. **플레이북 구조를 정의**하는 데 적합합니다.

### 2.2. `include_tasks` (동적 통합)

  * **특징**: 플레이북 실행 중 해당 지점에서 파일 내용을 읽어와 **동적으로** 통합합니다.
  * **용도**: 반복문(`loop`)이나 조건문(`when`)과 결합하여 **실행 시점에 파일 경로나 변수가 결정**될 때 유용합니다.

**💡 실전 팁 (Best Practice):**

  * 최신 Ansible 버전에서는 \*\*`include_tasks`\*\*를 사용하여 태스크를 동적으로 포함하는 것을 권장하며, `include`를 `include_tasks`로 대체하고 있습니다.
  * 반면, **Role 내에서 다른 Role을 호출**할 때는 \*\*`import_role`\*\*을 주로 사용하여 구조를 명확히 합니다.

**`include_tasks` 예제:**

```yaml
# main.yml 파일 내에서
- name: Loop through multiple configuration files
  ansible.builtin.include_tasks: "install_{{ item }}_service.yml"
  loop:
    - web
    - db
    - cache
  # 실행 시점에 "install_web_service.yml", "install_db_service.yml" 등을 동적으로 호출합니다.
```

## 3\. Jinja2 템플릿의 역할 구현 🧱

Jinja2 템플릿을 Role과 결합하여 구현하면, 인프라의 복잡한 설정을 깔끔하게 자동화할 수 있습니다.

### 3.1. Role 내 템플릿 배치

Jinja2 템플릿 파일(`*.j2`)은 해당 Role 디렉토리 내 **`templates`** 폴더에 위치해야 합니다.

```
/roles/
└── webserver/
    ├── tasks/
    │   └── main.yml
    └── templates/
        └── nginx.conf.j2  # Jinja2 템플릿 파일
```

### 3.2. 템플릿 파일에서 조건문 활용 예제

템플릿 파일 내에서 변수의 값에 따라 다른 설정을 적용하는 것은 실무에서 매우 유용합니다.

**`nginx.conf.j2` 예시:**

```nginx
server {
    listen {{ http_port }};
    server_name {{ inventory_hostname }}; # Ansible 기본 변수 사용

    # 변수 'environment' 값에 따라 로직 분기
    {% if environment == 'prod' %}
    # 프로덕션 환경일 경우에만 SSL 설정을 강제합니다.
    listen 443 ssl;
    ssl_certificate /etc/ssl/certs/prod.crt;
    ssl_certificate_key /etc/ssl/private/prod.key;
    {% else %}
    # 개발 환경일 경우 간단한 포트만 설정합니다.
    access_log /var/log/nginx/dev_access.log;
    {% endif %}

    root {{ web_root_path }};
    # ... (생략)
}
```

### 3.3. 플레이북에서 템플릿 적용

Ansible은 Role의 `tasks/main.yml`에서 `template` 모듈을 사용할 때, 자동으로 해당 Role의 `templates` 폴더를 탐색합니다.

```yaml
# roles/webserver/tasks/main.yml 내에서
- name: Configure Nginx Vhost using template
  ansible.builtin.template:
    src: nginx.conf.j2  # templates/nginx.conf.j2 파일을 사용
    dest: /etc/nginx/sites-available/default
  notify: restart nginx
```

이러한 **변수 관리, 태스크 제어, Jinja2 템플릿**의 조합을 통해, 모든 인프라 환경의 복잡한 설정을 중앙에서 코드화하고, 재사용하며, 안전하게 관리할 수 있는 전문적인 IaC 시스템이 완성됩니다.
