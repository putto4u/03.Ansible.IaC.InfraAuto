GitHub에 코드를 배포하고, 특정 제목의 이슈가 생성되었을 때 자동으로 서버에 코드를 배포하는 **GitOps 워크플로우**를 구축합니다.

## 1. GitHub 업로드 전 선행 작업 (보안 관리)

GitHub은 공용 저장소이므로 **서버 접속 키(.pem)**나 **민감한 설정**이 노출되면 안 됩니다. 이를 위해 `.gitignore` 파일을 작성하여 추적에서 제외해야 합니다.

### ① .gitignore 파일 생성

프로젝트 최상위 디렉토리(`nginx-role-project/`)에 생성합니다.

```text
# .gitignore
keys/*.pem          # 접속 키 제외
*.retry             # 앤서블 실행 실패 로그 제외
.DS_Store           # Mac 시스템 파일 제외

```

### ② 로컬 저장소 초기화 및 업로드

```bash
git init
git add .
git commit -m "Initial commit: Ansible Nginx Role Project"
# GitHub 리포지토리 생성 후 연결
git remote add origin https://github.com/사용자명/리포지토리명.git
git push -u origin main

```

## 2. GitHub Actions를 이용한 자동 배포 액션 구축

GitHub 상단 메뉴의 **[Actions]** 탭을 클릭하여 설정을 시작합니다.

### ① 접속 키 등록 (GitHub Secrets)

액션이 서버에 접속할 수 있도록 키 파일을 보안 저장소에 등록해야 합니다.

1. GitHub 리포지토리 페이지 우측 상단의 **[Settings]** 클릭
2. 좌측 메뉴에서 **[Secrets and variables]** -> **[Actions]** 클릭
3. **[New repository secret]** 버튼 클릭
* **Name**: `SSH_PRIVATE_KEY`
* **Secret**: `.pem` 파일의 내용 전체 복사/붙여넣기



### ② 액션 워크플로우 생성

1. 리포지토리 상단 **[Actions]** 메뉴 클릭
2. **"set up a workflow yourself"** 링크 클릭
3. 파일명을 `.github/workflows/deploy.yml`로 정하고 아래 코드를 복사합니다.

```yaml
name: Project Execution Action

on:
  issues:
    types: [opened] # 이슈가 새로 생성될 때 실행

jobs:
  deploy:
    # 이슈 제목이 "프로젝트명 실행"일 때만 작동
    if: contains(github.event.issue.title, '프로젝트명 실행')
    runs-on: ubuntu-latest

    steps:
      - name: 소스 코드 가져오기
        uses: actions/checkout@v3

      - name: SSH 키 설정
        run: |
          mkdir -p keys
          echo "${{ secrets.SSH_PRIVATE_KEY }}" > keys/your-aws-key.pem
          chmod 400 keys/your-aws-key.pem

      - name: 앤서블 설치 및 실행
        run: |
          sudo apt-get update
          sudo apt-get install -y ansible

          # 호스트 키 확인을 비활성화하여 yes/no 프롬프트 방지
          export ANSIBLE_HOST_KEY_CHECKING=False

          # 인벤토리의 서버들이 인터넷이 되므로 직접 접속하여 실행
          ansible-playbook -i inventory.yml deploy_site.yml \
          --extra-vars "ansible_become_password=${{ secrets.SUDO_PASSWORD }}"
          # sudo 권한(Become) 패스워드 자동 대응
```

## 3. 서버 측 선행 작업 (인벤토리 서버)

서버들이 Git 명령을 수행하고 앤서블 제어를 받으려면 각 서버에 최소한의 설정이 필요합니다.

* **SSH 접속 허용**: 로드밸런서와 웹 서버의 보안 그룹(Security Group)에서 GitHub Actions 호스트(또는 전체)에 대해 **22번 포트(SSH)**를 개방해야 합니다.
* **파이썬 설치**: 앤서블은 파이썬 기반이므로 모든 대상 서버에 `python3`가 설치되어 있어야 합니다. (Ubuntu 기본 포함)

## 4. 미션 수행 방법 (메뉴 위치 및 절차)

1. **GitHub Issues 메뉴로 이동**: 리포지토리 상단 탭 중 **[Issues]**를 클릭합니다.
2. **새 이슈 생성**: 우측 초록색 **[New issue]** 버튼을 누릅니다.
3. **제목 입력**: 제목란에 **`프로젝트명 실행`**이라고 정확히 입력합니다. (내용은 자유)
4. **제출**: **[Submit new issue]**를 누릅니다.
5. **실행 확인**: 상단 **[Actions]** 탭으로 가면 방금 생성한 이슈에 의해 배포 작업이 자동으로 시작되는 것을 볼 수 있습니다.

기존 프로젝트 내 파일들 중에서 **자동화(GitOps) 환경**에 맞게 반드시 수정하거나 보완해야 할 부분들이 있습니다. 특히 패스워드 입력 없이 실행되도록 하는 설정과, GitHub Actions에서 유동적으로 변수를 처리하기 위한 최적화 작업이 필요합니다.

## 1. 인벤토리 파일 수정 (`inventory.yml`)

가장 중요한 변경 사항입니다. 로컬 환경에서 사용하던 키 경로와 사용자 정보를 GitHub Actions 워크러 환경에 맞춰 동적으로 변경할 수 있도록 변수화합니다.

```yaml
all:
  children:
    load_balancer:
      hosts:
        lb_node:
          ansible_host: 192.168.10.100
    web_servers:
      hosts:
        web_01:
          ansible_host: 192.168.10.101
        web_02:
          ansible_host: 192.168.10.102
  vars:
    ansible_user: ubuntu
    # GitHub Actions에서 생성될 키 경로로 고정하거나 환경 변수 사용 가능하도록 설정
    ansible_ssh_private_key_file: "./keys/your-aws-key.pem"
    # [추가] 자동화를 위한 필수 설정: 호스트 키 검사 생략 및 비대화형 설정
    ansible_ssh_common_args: '-o StrictHostKeyChecking=no'

```

## 2. 메인 플레이북 최적화 (`deploy_site.yml`)

플레이북 실행 시 발생할 수 있는 '연결 대기' 문제를 방지하기 위해 `gather_facts` 설정을 점검하고, 핸들러 호출 방식을 명확히 합니다.

```yaml
---
- name: 백엔드 웹 서버 계층 배포
  hosts: web_servers
  become: true
  gather_facts: true  # 호스트 정보를 수집해야 템플릿의 group_names 등을 사용 가능
  roles:
    - webserver

- name: 전면 로드 밸런서 계층 배포
  hosts: load_balancer
  become: true
  roles:
    - loadbalancer
  
  # 핸들러를 역할 외부에서 별도로 로드할 때의 경로 주의
  handlers:
    - name: "Import Global Handlers"
      ansible.builtin.import_tasks: handlers/main.yml

```

## 3. 핸들러 파일 가독성 보완 (`handlers/main.yml`)

자동화 실행 중 어떤 핸들러가 작동했는지 로그에서 쉽게 파악할 수 있도록 이름을 명확히 수정합니다.

```yaml
---
- name: "Universal Service Controller"
  ansible.builtin.service:
    name: "{{ (group_names | intersect(['web_servers', 'load_balancer'])) | length > 0 | ternary('nginx', 'mysql') }}"
    state: "{{ 'reloaded' if 'web_servers' in group_names else 'restarted' }}"
  listen: "trigger_restart"

# 팁: 자동화 로그 확인을 위해 아래처럼 명시적인 핸들러를 유지하는 것이 좋습니다.
- name: "Restart Nginx for Web Group"
  ansible.builtin.service:
    name: nginx
    state: reloaded
  when: "'web_servers' in group_names"
  listen: "trigger_restart"

```

## 4. GitHub Actions 워크플로우 보완 (`deploy.yml`)

GitHub Secrets에서 가져온 키 파일의 이름을 `inventory.yml`에 정의된 파일명과 정확히 일치시켜야 에러가 나지 않습니다.

```yaml
      - name: SSH 키 설정
        run: |
          mkdir -p keys
          # inventory.yml에 기재한 파일명(your-aws-key.pem)과 동일하게 생성
          echo "${{ secrets.SSH_PRIVATE_KEY }}" > keys/your-aws-key.pem
          chmod 400 keys/your-aws-key.pem

      - name: 앤서블 실행
        run: |
          # 환경변수로 호스트 키 체크 비활성화를 한 번 더 확실히 지정
          export ANSIBLE_HOST_KEY_CHECKING=False
          ansible-playbook -i inventory.yml deploy_site.yml

```

### 수정 시 주의사항 (Checklist)

* **파일명 일치**: `inventory.yml`의 `ansible_ssh_private_key_file` 경로와 액션에서 생성하는 `.pem` 파일명이 반드시 같아야 합니다.
* **권한 문제**: `.pem` 파일은 반드시 `chmod 400` 처리가 되어야 SSH 접속이 거부되지 않습니다.
* **인터넷 연결**: 모든 대상 서버(EC2 등)는 외부에서 SSH(22번 포트) 접속이 가능하도록 보안 그룹이 열려 있어야 합니다.
