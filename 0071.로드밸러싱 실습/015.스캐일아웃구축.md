## 동적 확장성을 고려한 Nginx 웹 서버 및 로드 밸런서 구축 프로젝트

서버 대수가 3대에서 10대, 100대로 늘어나더라도 **코드 수정 없이 인벤토리 파일만 업데이트하면 즉시 반영되는** 동적 확장 구조로 설계되었습니다. Ansible의 그룹 변수와 Jinja2 반복문을 활용하여 서버 수에 관계없이 유연하게 작동합니다.

---

### 1. 프로젝트 개요 및 확장성 특장점

* **자동 업스트림 구성**: 로드 밸런서 설정 시 `web_servers` 그룹에 속한 모든 서버를 자동으로 탐색하여 Nginx 설정에 추가합니다.
* **유연한 스케일 아웃**: 새로운 웹 서버가 추가되면 `inventory.yml`에 IP만 한 줄 추가하고 플레이북을 실행하면 로드 밸런서가 즉시 새 서버를 인식합니다.
* **역할 기반 관리**: Role 구조를 유지하여 서버 설치 로직과 네트워크 설정 로직이 서로 간섭하지 않도록 분리했습니다.

---

### 2. 프로젝트 디렉토리 구조 (표준)

```text
nginx-scalable-project/
├── inventory.yml                # 관리 대상 서버 리스트 (서버 증설 시 이곳만 수정)
├── deploy_site.yml              # 전체 시스템 배포 메인 파일
└── roles/
    ├── webserver/
    │   └── tasks/
    │       └── main.yml         # 웹 서버 설치 로직
    └── loadbalancer/
        ├── tasks/
        │   └── main.yml         # LB 설정 및 템플릿 배포
        └── templates/
            └── lb_nginx.conf.j2 # [핵심] 서버 수에 따라 가변적으로 변하는 설정

```

### 3. 확장형 소스 코드

#### ① 인벤토리 파일 (`inventory.yml`)

서버가 늘어나면 아래 `web_servers` 항목에 호스트명과 IP만 추가하면 됩니다.

```yaml
all:
  children:
    load_balancer:
      hosts:
        lb_node:
          ansible_host: 192.168.10.100    # 로드밸런서 IP
    web_servers:
      hosts:
        web_01:
          ansible_host: 192.168.10.101    # 웹 서버 1
        web_02:
          ansible_host: 192.168.10.102    # 웹 서버 2
        web_03:
          ansible_host: 192.168.10.103    # (예시) 서버 추가 시 한 줄만 추가
        # 추가되는 서버들을 여기에 계속 나열 가능

```

#### ② 메인 플레이북 (`deploy_site.yml`)

```yaml
---
- name: 백엔드 웹 서버 계층 확장 배포
  hosts: web_servers                     # 인벤토리에 등록된 모든 웹 서버 대상
  become: true
  roles:
    - webserver

- name: 전면 로드 밸런서 동적 설정 갱신
  hosts: load_balancer
  become: true
  roles:
    - loadbalancer

```

#### ③ 웹 서버 역할 (`roles/webserver/tasks/main.yml`)

```yaml
---
- name: Nginx 설치
  ansible.builtin.apt:
    name: nginx
    state: present
    update_cache: true

- name: 동적 호스트 이름을 포함한 페이지 생성
  ansible.builtin.copy:
    content: "<h1>Server: {{ inventory_hostname }} (IP: {{ ansible_host }})</h1>"
    dest: /var/www/html/index.html
    mode: '0644'

```

#### ④ 로드 밸런서 역할 (`roles/loadbalancer/tasks/main.yml`)

```yaml
---
- name: Nginx 설치
  ansible.builtin.apt:
    name: nginx
    state: present
    update_cache: true

- name: 기존 설정 제거
  ansible.builtin.file:
    path: /etc/nginx/sites-enabled/default
    state: absent

- name: [확장형] 로드 밸런싱 설정 템플릿 배포
  ansible.builtin.template:
    src: lb_nginx.conf.j2
    dest: /etc/nginx/conf.d/load_balancer.conf
    mode: '0644'
  notify: Restart Nginx

  handlers:
    - name: Restart Nginx
      ansible.builtin.service:
        name: nginx
        state: restarted

```

#### ⑤ [핵심] 확장형 설정 템플릿 (`roles/loadbalancer/templates/lb_nginx.conf.j2`)

이 코드가 인벤토리의 서버 대수를 계산하여 Nginx 설정을 완성합니다.

```nginx
upstream my_backend_servers {
    # web_servers 그룹에 정의된 서버 수만큼 자동으로 server 행을 생성합니다.
    {% for host in groups['web_servers'] %}
    server {{ hostvars[host]['ansible_host'] }}:80 max_fails=3 fail_timeout=30s;
    {% endfor %}
}

server {
    listen 80;
    server_name localhost;

    location / {
        proxy_pass http://my_backend_servers;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        
        # 실제 어떤 백엔드 서버가 처리했는지 확인하는 헤더
        add_header X-Backend-Server $upstream_addr;
    }
}

```

### 4. AWS 운영 및 과금 가이드 (확장 시 주의사항)

* **인스턴스 개수별 과금**: 웹 서버 대수가 늘어날수록 **EC2 인스턴스 시간당 비용**과 **EBS 스토리지 비용**이 정비례하여 증가합니다. 실습 시에는 2~3대로 충분하며, 대규모 확장 테스트 후에는 반드시 모든 인스턴스를 종료해야 합니다.
* **보안 그룹(Security Group) 관리**:
* 서버가 늘어나더라도 모든 웹 서버는 동일한 **Web SG**를 공유하도록 설정하세요.
* **Web SG**의 인바운드 규칙에 **LB SG**를 소스(Source)로 등록해두면, 서버가 100대로 늘어나도 별도의 보안 설정 수정이 필요 없습니다.


* **네트워크 대역폭**: 서버가 많아지고 트래픽이 증가하면 AWS 리전 내 데이터 전송 비용이나 로드 밸런서의 처리 용량(Bandwidth) 한계에 부딪힐 수 있으니 모니터링이 필요합니다.
