## Ansible Role 기반 Nginx 웹 서버 및 로드 밸런서 분리 구축 프로젝트

본 프로젝트는 실무 표준 방식인 **Role(역할) 구조**를 채택하여 설계되었습니다. 웹 서버 설치 로직과 로드 밸런서 설정 로직을 물리적으로 분리함으로써, 향후 서버 증설이나 설정 변경 시 필요한 부분만 골라 실행할 수 있는 유연한 인프라 구조를 지향합니다.

---

### 1. 프로젝트 개요 및 특장점

* **역할 분리 (Roles)**: 웹 서버(`webserver`)와 로드 밸런서(`loadbalancer`)의 태스크를 독립된 디렉토리로 격리하여 가독성과 재사용성을 극대화했습니다.
* **동적 확장성**: `inventory.yml`의 `web_servers` 그룹에 IP만 추가하면, 로드 밸런서 템플릿이 이를 자동으로 감지하여 업스트림 리스트를 갱신합니다.
* **GitOps 친화적**: 각 역할이 독립적이기 때문에 특정 기능의 코드 변경 사항을 추적하기 쉬우며, 대규모 프로젝트로 확장 시 관리가 용이합니다.

---

### 2. 프로젝트 디렉토리 구조

실습을 시작하기 전, 아래와 같은 구조로 폴더와 파일을 생성해 주세요. 보안을 위해 AWS 접속 키를 보관하는 **`keys/`** 디렉토리를 추가하고, 핸들러 코드 중복을 통합하였습니다.

```text
nginx-role-project/
├── inventory.yml                 # 전체 서버 그룹 및 IP 정의
├── deploy_site.yml               # 전체 시스템 구축용 메인 플레이북
├── keys/                         # [추가] AWS EC2 접속 키 (.pem) 보관 디렉토리
├── handlers/                     # [통합] 전역 핸들러 보관함
│   └── main.yml                  # 모든 서버가 공유하는 통합 핸들러 (Listen 활용)
├── roles/                        # 역할별 로직 보관함
│   ├── webserver/
│   │   └── tasks/
│   │       └── main.yml          # 웹 서버 설치 및 index.html 생성
│   └── loadbalancer/
│       ├── tasks/
│       │   └── main.yml          # LB 설치 및 설정 배포
│       └── templates/
│           └── lb_nginx.conf.j2  # LB 설정 템플릿

```

### 3. 주요 파일별 소스 코드

#### ① 키 보관 및 권한 설정 (사전 작업)

AWS에서 다운로드한 `.pem` 키 파일을 `keys/` 디렉토리에 배치하고 보안 권한을 설정합니다.

```bash
# keys 디렉토리 생성
mkdir keys

# 다운로드한 키 파일을 keys 디렉토리로 이동 (파일명은 실제 본인 파일명에 맞춤)
mv your-aws-key.pem keys/

# 키 파일 보안 설정: 소유자에게만 읽기 권한 부여 (SSH 접속 필수 조건)
chmod 400 keys/your-aws-key.pem

```

#### ② 통합 핸들러 파일 (`handlers/main.yml`)

```yaml
---
# 전역 지능형 핸들러: 그룹명에 따라 서비스 명과 동작을 동적으로 결정하여 실행
- name: "Universal Service Controller"
  ansible.builtin.service:
    # web_servers나 load_balancer 그룹에 속해 있으면 nginx를, 아니면 mysql을 대상으로 설정
    name: "{{ (group_names | intersect(['web_servers', 'load_balancer'])) | length > 0 | ternary('nginx', 'mysql') }}"
    # web_servers 그룹이면 reloaded를, 그 외에는 restarted 상태로 변경
    state: "{{ 'reloaded' if 'web_servers' in group_names else 'restarted' }}"
  listen: "trigger_restart" # 태스크에서 호출할 공통 별칭

# 명시적 관리를 위한 그룹별 핸들러 (IAC 가독성 확보)
- name: "Restart Web Services"
  ansible.builtin.service:
    name: nginx
    state: reloaded # 웹 서버는 무중단 반영을 위해 리로드 권장
  when: "'web_servers' in group_names" # 현재 작업 호스트가 web_servers 그룹일 때만 실행
  listen: "trigger_restart"

- name: "Restart LB Services"
  ansible.builtin.service:
    name: nginx
    state: restarted # 로드밸런서는 설정 적용을 위해 재시작
  when: "'load_balancer' in group_names" # 현재 작업 호스트가 load_balancer 그룹일 때만 실행
  listen: "trigger_restart"

- name: "Restart DB Services"
  ansible.builtin.service:
    name: mysql
    state: restarted # DB 서버 재시작
  when: "'db_servers' in group_names" # 현재 작업 호스트가 db_servers 그룹일 때만 실행
  listen: "trigger_restart"

```

#### ③ 인벤토리 파일 (`inventory.yml`)

```yaml
all:
  children:
    load_balancer: # 로드 밸런서 그룹 정의
      hosts:
        lb_node:
          ansible_host: 192.168.10.100 # 로드밸런서용 EC2 공인 IP
    web_servers: # 백엔드 웹 서버 그룹 정의
      hosts:
        web_01:
          ansible_host: 192.168.10.101 # 웹 서버 1 공인 IP
        web_02:
          ansible_host: 192.168.10.102 # 웹 서버 2 공인 IP
  vars:
    ansible_user: ubuntu # AWS Ubuntu 인스턴스 기본 사용자명
    ansible_ssh_private_key_file: "./keys/your-aws-key.pem" # 상대 경로를 통한 키 파일 지정

```

#### ④ 메인 플레이북 (`deploy_site.yml`)

```yaml
---
# 1단계: 백엔드 웹 서버 그룹에 대한 설정 배포
- name: 백엔드 웹 서버 계층 배포
  hosts: web_servers
  become: true # sudo 권한 획득
  roles:
    - webserver # roles/webserver/tasks/main.yml 실행

# 2단계: 전면 로드 밸런서 그룹에 대한 설정 배포
- name: 전면 로드 밸런서 계층 배포
  hosts: load_balancer
  become: true # sudo 권한 획득
  roles:
    - loadbalancer # roles/loadbalancer/tasks/main.yml 실행

  # 모든 역할에서 발생하는 notify 신호를 수신하기 위한 전역 핸들러 로드
  handlers:
    - import_tasks: handlers/main.yml

```

#### ⑤ 웹 서버 역할 (`roles/webserver/tasks/main.yml`)

```yaml
---
# APT 패키지 매니저를 사용하여 최신 버전의 Nginx 설치
- name: Nginx 웹 서버 패키지 설치
  ansible.builtin.apt:
    name: nginx
    state: present # 설치되어 있어야 함을 명시
    update_cache: true # 설치 전 apt update 실행

# 각 서버를 구분할 수 있도록 호스트 이름을 포함한 index.html 파일 생성
- name: 서버별 개별 식별 페이지 생성
  ansible.builtin.copy:
    content: "<h1>Hello! This is {{ inventory_hostname }}</h1>"
    dest: /var/www/html/index.html
    mode: '0644' # 파일 권한 설정
  notify: "trigger_restart" # 파일 변경 시 통합 핸들러 호출

```

#### ⑥ 로드 밸런서 역할 (`roles/loadbalancer/tasks/main.yml`)

```yaml
---
# LB 역할도 Nginx 기반이므로 패키지 설치 진행
- name: Nginx 로드 밸런서 패키지 설치
  ansible.builtin.apt:
    name: nginx
    state: present
    update_cache: true

# Nginx의 기본 환영 페이지 설정 파일을 삭제하여 충돌 방지
- name: 기본 설정 파일 제거
  ansible.builtin.file:
    path: /etc/nginx/sites-enabled/default
    state: absent # 파일이 존재하지 않아야 함을 명시

# Jinja2 템플릿을 사용하여 인벤토리 기반의 동적 로드밸런싱 설정 배포
- name: 로드 밸런싱 설정 템플릿 배포
  ansible.builtin.template:
    src: lb_nginx.conf.j2
    dest: /etc/nginx/conf.d/load_balancer.conf
    mode: '0644'
  notify: "trigger_restart" # 설정 변경 시 통합 핸들러 호출

```

#### ⑦ LB 설정 템플릿 (`roles/loadbalancer/templates/lb_nginx.conf.j2`)

```nginx
# 백엔드 서버 그룹 정의: 인벤토리의 web_servers 그룹 IP를 자동으로 리스팅
upstream my_backend_servers {
    {% for host in groups['web_servers'] %}
    server {{ hostvars[host]['ansible_host'] }}:80 max_fails=3 fail_timeout=30s;
    {% endfor %}
}

server {
    listen 80;
    server_name localhost;

    location / {
        proxy_pass http://my_backend_servers; # 위에서 정의한 그룹으로 트래픽 전달
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        
        # 실제 어떤 백엔드 서버가 응답했는지 브라우저 헤더에서 확인 가능하게 설정
        add_header X-Backend-Server $upstream_addr;
    }
}

```

### 4. 프로젝트 실행 및 확인 방법

#### ① 실행 명령줄

플레이북을 실행하기 전 인벤토리 정보를 확인하고 실행합니다.

```bash
# 1. 인벤토리 연결 테스트 (모든 서버 접속 확인)
ansible all -i inventory.yml -m ping

# 2. 메인 플레이북 실행
ansible-playbook -i inventory.yml deploy_site.yml

```

#### ② 결과 확인 방법

1. **브라우저 접속**: 로드밸런서 서버의 IP(`192.168.10.100`)로 접속합니다.
2. **새로고침 테스트**: 브라우저를 새로고침할 때마다 `web_01`과 `web_02`가 번갈아 가며 나타나는지 확인합니다.
3. **헤더 확인**: 개발자 도구(F12) -> Network 탭에서 응답 헤더의 `X-Backend-Server` 항목을 통해 실제 처리 서버 IP를 확인합니다.

### 5. AWS 운영 시 과금 및 보안 가이드

* **EC2 고정 비용**: 로드 밸런서용 1대와 웹 서버용 2대, 총 3대의 인스턴스가 상시 가동되어야 합니다. 프리티어 기간이 종료된 경우 시간당 인스턴스 비용이 각각 청구됩니다.
* **공인 IP (EIP) 과금 주의**: 인스턴스를 중지하더라도 연결된 공인 IP가 있으면 시간당 약 **$0.005**가 부과됩니다.
* **보안 그룹 최적화**:
* **LB SG**: 포트 80을 `0.0.0.0/0` (전체)에 개방합니다.
* **Web SG**: 포트 80을 오직 **LB의 보안 그룹 ID**로부터의 트래픽만 허용하여 직접 노출을 차단하세요.


* **자원 회수**: 실습 종료 직후 모든 인스턴스를 **Terminate(종료)** 해야 추가 과금을 방지할 수 있습니다.
