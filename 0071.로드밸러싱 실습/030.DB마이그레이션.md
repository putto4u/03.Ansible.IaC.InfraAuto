## DB 마이그레이션 및 고가용성 환경 구축 프로젝트

이 프로젝트는 인터넷에 공개된 데이터를 활용하여 실제 서비스 환경과 유사한 **DB 마이그레이션** 과정을 자동화합니다. 2대의 DB 서버를 사용하여 쓰기 전용 마스터와 읽기 전용 슬레이브로 구성하며, 마스터에서 실행된 마이그레이션 작업이 슬레이브로 어떻게 안전하게 전파되는지 실습합니다.

---

### 1. 로드 밸런싱 및 복제 환경에서의 DB 마이그레이션 단계

성공적인 마이그레이션을 위해 아래와 같은 엄격한 단계를 거칩니다. 이는 서버 대수가 늘어나도 동일하게 적용되는 표준 절차입니다.

1. **쓰기 엔드포인트(Master) 타겟팅**: 모든 DB 마이그레이션 작업은 반드시 쓰기 권한이 있는 **마스터 서버** 한 곳에서만 수행되어야 합니다.
2. **데이터 소스 확보**: 공식 저장소로부터 마이그레이션 대상 SQL 데이터와 테이블 구조 파일을 마스터 서버의 임시 디렉토리에 다운로드합니다.
3. **트랜잭션 기반 주입**: 마스터 서버에서 SQL 주입을 실행합니다. 이 과정에서 발생하는 모든 데이터 변경 사항은 마스터의 **바이너리 로그(Binary Log)**에 기록됩니다.
4. **복제 전파 (Replication Propagation)**: 마스터의 로그가 슬레이브 서버로 실시간 전송됩니다. 슬레이브는 이 로그를 실행하여 마스터와 동일한 데이터 상태를 유지합니다.
5. **무결성 검증**: 마이그레이션 완료 후, 로드 밸런서를 통해 읽기 쿼리를 수행하여 마스터와 슬레이브 간의 데이터 일치 여부를 최종 확인합니다.

### 2. 프로젝트 디렉토리 구조

이전 웹 서버 및 LB 프로젝트와 동일한 형식을 유지하여 통합 배포가 가능하도록 설계되었습니다.

```text
db-migration-project/
├── inventory.yml                # [중요] DB 2대 구성 인벤토리
├── deploy_migration.yml         # DB 마이그레이션 실행 메인 플레이북
└── roles/
    └── mysql_migration/
        └── tasks/
            └── main.yml         # 마이그레이션 세부 로직 (주석 포함)

```

### 3. 주요 파일별 소스 코드 (DB 2대 구성)

#### ① 인벤토리 파일 (`inventory.yml`)

이전 프로젝트와 형식을 일치시키되, 실습 목적에 맞게 DB 대수를 2대로 조정했습니다.

```yaml
all:
  children:
    db_master:                   # 쓰기 및 마이그레이션 원본 그룹
      hosts:
        db_01:                   # 1번 서버 (Master)
          ansible_host: 192.168.20.101
    db_slave:                    # 읽기 및 복제 대상 그룹
      hosts:
        db_02:                   # 2번 서버 (Slave)
          ansible_host: 192.168.20.102

```

#### ② 마이그레이션 역할 (`roles/mysql_migration/tasks/main.yml`)

데이터 다운로드부터 주입 완료까지의 모든 과정에 주석을 달았습니다.

```yaml
---
- name: Git 설치                                 # 외부 저장소에서 데이터를 받기 위해 Git 설치
  ansible.builtin.apt:
    name: git
    state: present
    update_cache: true

- name: 마이그레이션 대상 데이터 다운로드            # GitHub에서 마이그레이션용 SQL 소스 클론
  ansible.builtin.git:
    repo: 'https://github.com/datacharmer/test_db.git'
    dest: /tmp/migration_data                   # 마스터 서버 내 임시 저장소
    clone: yes
    update: yes

- name: DB 마이그레이션 실행 (마스터 주입)           # 마스터 서버에 데이터 주입 (슬레이브로 자동 복제됨)
  ansible.builtin.shell:
    cmd: mysql -t < employees.sql               # 테이블 구조 및 데이터 주입 실행
    chdir: /tmp/migration_data                  # 파일이 위치한 경로에서 실행
  register: migration_result                    # 실행 결과 로그 저장
  changed_when: true                            # 멱등성 유지를 위해 변경됨으로 표시

- name: 마이그레이션 데이터 무결성 확인              # 주입된 사원 데이터의 총 건수 확인
  ansible.builtin.shell:
    cmd: mysql -e "SELECT count(*) FROM employees.employees;"
  register: record_count

- name: 마이그레이션 완료 리포트                     # 최종 주입 결과를 화면에 출력
  ansible.builtin.debug:
    msg: "DB 마이그레이션 성공! 주입된 총 사원 수: {{ record_count.stdout }}"

- name: 임시 작업 디렉토리 제거                    # 보안 및 용량 최적화를 위해 임시 파일 삭제
  ansible.builtin.file:
    path: /tmp/migration_data
    state: absent

```

### 4. AWS 운영 및 과금 가이드

* **인스턴스 개수 (2대)**: 웹 서버(3대)와 합쳐도 총 5대 규모로, 프리티어 750시간을 안정적으로 나누어 쓸 수 있는 수량입니다.
* **유료 전환 주의 (EBS)**:
* 마이그레이션되는 데이터 양에 따라 디스크 사용량이 늘어납니다. 인스턴스 5대 합산 **EBS 용량이 30GB를 넘으면 즉시 유료 과금**이 발생하므로, 각 인스턴스 생성 시 용량을 8GB 내외로 설정하세요.


* **네트워크 비용**: 외부(GitHub) 데이터를 마스터로 가져오는 것은 무료이나, 마스터에서 슬레이브로 데이터를 전송(복제)할 때 AWS 리전 간 이동이 발생하면 **데이터 전송 비용**이 청구될 수 있습니다. (동일 가용 영역 내 실습 권장)
* **보안 그룹**: 마스터 서버는 마이그레이션 도중 외부(Git)와 통신해야 하므로 **Outbound 443(HTTPS)** 포트가 열려 있어야 합니다.
* **리소스 정리**: 마이그레이션 실습이 완료되면 추가 비용 방지를 위해 모든 인스턴스를 반드시 **Terminate(종료)** 하십시오.
